> สรุป: Phone Number plugin สำหรับ Managed Better Auth เพิ่มการเข้าสู่ระบบด้วย SMS OTP สำหรับผู้ใช้ที่มีอยู่แล้ว เมื่อผู้ใช้ส่งหมายเลขโทรศัพท์ในรูปแบบ E.164 Managed Better Auth จะเรียกเว็บฮุก `send.otp` พร้อมรหัสตัวเลขที่ handler ของคุณส่งต่อไปยังผู้ให้บริการ SMS (Twilio, Vonage, MessageBird เป็นต้น) ใช้หน้านี้เมื่อต้องการให้ผู้ใช้ที่มีหมายเลขโทรศัพท์ที่ยืนยันแล้วเชื่อมโยงกับบัญชีสามารถเข้าสู่ระบบด้วย phone OTP ได้ โดยยังไม่รองรับการสมัครสมาชิกโดยเริ่มจากหมายเลขโทรศัพท์ สามารถกำหนดเวลาหมดอายุของ OTP ได้, request มี rate limit ต่อ IP และ OTP จะถูกทำให้ใช้ไม่ได้หลังจากกรอกรหัสผิดมากเกินจำนวนที่กำหนด

# Phone Number

ให้ผู้ใช้ที่มีอยู่แล้วเข้าสู่ระบบด้วยรหัส phone OTP ที่ส่งผ่านผู้ให้บริการ SMS ของคุณ

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

Managed Better Auth สร้างขึ้นบน [Better Auth](https://www.better-auth.com/) และรองรับปลั๊กอิน [Phone Number](https://www.better-auth.com/docs/plugins/phone-number) ผ่าน Neon SDK

Phone Number ช่วยให้ผู้ใช้ที่มีอยู่แล้วเข้าสู่ระบบด้วยรหัสผ่านแบบใช้ครั้งเดียว (OTP) ที่ส่งไปยังโทรศัพท์ โดยโฟลว์ทำงานดังนี้:

1. ผู้ใช้กรอกหมายเลขโทรศัพท์ในรูปแบบ E.164 (ตัวอย่างเช่น `+15551234567`)
2. Managed Better Auth สร้าง OTP 6 หลักและเรียกเว็บฮุก `send.otp` พร้อม `delivery_preference: "sms"` จากนั้น webhook handler ของคุณจะส่งรหัสผ่านผู้ให้บริการ SMS
3. ผู้ใช้กรอกรหัส Managed Better Auth จะตรวจสอบรหัส สร้างเซสชัน และเข้าสู่ระบบให้ผู้ใช้

**สำคัญ:** Phone Number plugin ใช้สำหรับ **sign-in เท่านั้น** ผู้ใช้ต้องมีอยู่ในโปรเจ็กต์ของคุณแล้วและมีหมายเลขโทรศัพท์เชื่อมโยงกับบัญชี ไม่มีโฟลว์สมัครสมาชิกที่เริ่มจากหมายเลขโทรศัพท์

Managed Better Auth **ไม่ได้** ส่ง SMS ให้คุณ ปลั๊กอินต้องใช้เว็บฮุก `send.otp` ที่ส่งต่อรหัสไปยังผู้ให้บริการ SMS ของคุณ (Twilio, MessageBird, Vonage เป็นต้น)

## ข้อกำหนดเบื้องต้น

- โปรเจ็กต์ Neon ที่ **เปิดใช้งาน Auth** แล้ว
- ผู้ใช้ที่มีอยู่แล้วและมีหมายเลขโทรศัพท์เชื่อมโยงกับบัญชี
- เว็บฮุกที่ subscribe event `send.otp` และส่งต่อรหัสไปยังผู้ให้บริการ SMS ของคุณ (ดู [คู่มือ Webhooks](https://neon.com/docs/auth/guides/webhooks))

## เปิดใช้งาน Phone Number

**Console**

1. เปิด [Neon Console](https://console.neon.tech)
2. เลือกโปรเจ็กต์ของคุณแล้วไปที่ **Auth** > **Plugins**
3. เปิด toggle **Phone Authentication**
4. ตั้งค่าตัวเลือก:
   - **OTP Expiry** (60-600 วินาที, ค่าเริ่มต้น: 300) กำหนดว่า OTP ที่สร้างขึ้นจะใช้งานได้นานเท่าใด

![แท็บ Auth Plugins ใน Neon Console พร้อมการตั้งค่า Phone Number](https://neon.com/docs/auth/neon_auth_plugins_phone_number.png)

**API**

ตั้งค่า Phone Number plugin ด้วย request แบบ `PATCH` ฟิลด์ทั้งหมดใน request body เป็นตัวเลือก ให้ส่งเฉพาะฟิลด์ที่คุณต้องการเปลี่ยน ส่วน `GET` ที่ endpoint เดียวกันจะคืนการตั้งค่าปัจจุบัน

```bash
curl -X PATCH \
  "https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth/plugins/phone-number" \
  -H "Authorization: Bearer $NEON_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "otp_expires_in": 300
  }'
```

ทั้ง `PATCH` และ `GET` จะคืนการตั้งค่า:

```json
{
  "enabled": true,
  "otp_expires_in": 300
}
```

| Field            | Type    | Default | คำอธิบาย                                  |
| ---------------- | ------- | ------- | ----------------------------------------- |
| `enabled`        | boolean | `false` | ระบุว่า Phone Number plugin เปิดใช้งานอยู่หรือไม่ |
| `otp_expires_in` | integer | `300`   | จำนวนวินาทีก่อน OTP หมดอายุ (60-600)      |

## ส่ง OTP ผ่านผู้ให้บริการ SMS ของคุณ

Managed Better Auth จะเรียกเว็บฮุก `send.otp` พร้อม `delivery_preference: "sms"` เมื่อจำเป็นต้องส่ง OTP โดย handler ของคุณต้องส่งรหัสผ่านผู้ให้บริการ SMS (Twilio, MessageBird, Vonage เป็นต้น) หากไม่มีเว็บฮุก `send.otp` การเรียก `authClient.phoneNumber.sendOtp()` จะล้มเหลว

ตั้งค่าเว็บฮุกที่ subscribe `send.otp` (ดู [คู่มือ Webhooks](https://neon.com/docs/auth/guides/webhooks) สำหรับวิธีตั้งค่าและตรวจสอบลายเซ็นแบบครบถ้วน) จากนั้นแยกการทำงานตาม `delivery_preference` ใน handler:

```ts filename="app/api/webhooks/neon-auth/route.ts"
import { NextResponse } from 'next/server';
import twilio from 'twilio';

const twilioClient = twilio(
  process.env.TWILIO_ACCOUNT_SID!,
  process.env.TWILIO_AUTH_TOKEN!
);

export async function POST(request: Request) {
  const payload = await request.json(); // verify the signature first in production

  if (payload.event_type === 'send.otp' && payload.event_data.delivery_preference === 'sms') {
    const toNumber = payload.user?.phone_number;
    if (!toNumber) {
      return NextResponse.json({ error: 'missing phone number' }, { status: 400 });
    }

    await twilioClient.messages.create({
      from: process.env.TWILIO_FROM_NUMBER!,
      to: toNumber,
      body: `Your code is ${payload.event_data.otp_code}.`,
    });
  }

  return NextResponse.json({ ok: true });
}
```

**หมายเหตุ: ข้อมูลผู้ใช้สำหรับ OTP ครั้งแรก**

เมื่อผู้ใช้ที่ยังไม่ได้ยืนยันตัวตนขอ phone OTP ครั้งแรก (ยังไม่มีบัญชีก่อนหน้าที่เชื่อมโยงกับหมายเลขโทรศัพท์นั้น) ออบเจ็กต์ `user` ในเว็บฮุกจะมีเฉพาะ `phone_number` เท่านั้น อย่าพึ่งพา `user.name`, `user.email` หรือฟิลด์โปรไฟล์อื่นเมื่อสร้างข้อความ SMS สำหรับการส่งครั้งแรก

สำหรับ Next.js handler ที่รันได้จริง, การตรวจสอบลายเซ็น และการตั้งค่า tunneling สำหรับ local โปรดดู [ตัวอย่าง nextjs-phone-login](https://github.com/neondatabase/neon-js/tree/main/examples/nextjs-phone-login)

## เชื่อมโยงหมายเลขโทรศัพท์กับผู้ใช้

เชื่อมโยงโทรศัพท์กับผู้ใช้ที่มีอยู่แล้วจาก authenticated session โดยเรียก `authClient.phoneNumber.verify()` พร้อม `updatePhoneNumber: true`:

```ts filename="src/link-phone-number.ts"
import { authClient } from '@/lib/auth/client';

export async function sendLinkingOtp(phoneNumber: string) {
  const { error } = await authClient.phoneNumber.sendOtp({ phoneNumber });
  if (error) throw error;
}

export async function linkPhoneNumber(phoneNumber: string, code: string) {
  const { data, error } = await authClient.phoneNumber.verify({
    phoneNumber,
    code,
    updatePhoneNumber: true,
  });

  if (error) throw error;
  return data;
}
```

สำหรับฟอร์ม "Add phone number" แบบครบถ้วนพร้อม state ที่อิงตามเซสชัน (ไม่มีหมายเลข, ยังไม่ยืนยัน, ยืนยันแล้ว) โปรดดูคอมโพเนนต์ `AddPhoneForm` ใน [ตัวอย่าง nextjs-phone-login](https://github.com/neondatabase/neon-js/tree/main/examples/nextjs-phone-login)

## เข้าสู่ระบบผู้ใช้ที่มีอยู่แล้วด้วย phone OTP

สร้างฟอร์มเข้าสู่ระบบด้วยโทรศัพท์แบบสองขั้นตอน: ส่ง OTP แล้วจึงตรวจสอบรหัส **อย่า** ส่ง `updatePhoneNumber` การละค่านี้จะบอก Better Auth ให้เข้าสู่ระบบผู้ใช้ที่มีอยู่แล้ว แทนที่จะเชื่อมโยงหมายเลขโทรศัพท์:

```ts filename="src/phone-otp.ts"
import { authClient } from '@/lib/auth/client';

export async function sendPhoneOtp(phoneNumber: string) {
  const { error } = await authClient.phoneNumber.sendOtp({ phoneNumber });
  if (error) throw error;
}

export async function signInWithPhoneOtp(phoneNumber: string, code: string) {
  const { data, error } = await authClient.phoneNumber.verify({
    phoneNumber,
    code,
  });

  if (error) throw error;
  return data;
}
```

สำหรับฟอร์มที่ทำงานได้ครบถ้วนพร้อม resend, error handling และการรับรู้ attempt budget โปรดดู [ตัวอย่าง nextjs-phone-login](https://github.com/neondatabase/neon-js/tree/main/examples/nextjs-phone-login)

## ใช้ Phone Number ร่วมกับคอมโพเนนต์ UI

ต่างจาก Email OTP, `NeonAuthUIProvider` ไม่มี prop `phoneNumber` และ `AuthView` สำเร็จรูปจะไม่เรนเดอร์ UI สำหรับการเข้าสู่ระบบด้วยโทรศัพท์ หากคุณใช้คอมโพเนนต์ Managed Better Auth UI ให้เรนเดอร์ฟอร์มเข้าสู่ระบบด้วยโทรศัพท์ของคุณเองข้าง `AuthView` บน route เข้าสู่ระบบ:

```tsx filename="app/auth/[path]/page.tsx"
import { AuthView } from '@neondatabase/auth-ui';
import { authViewPaths } from '@neondatabase/auth-ui/server';
import { PhoneSignInSection } from './phone-sign-in-section'; // your own component

export default async function AuthPage({ params }: { params: Promise<{ path: string }> }) {
  const { path } = await params;
  const isSignIn = path === authViewPaths.SIGN_IN;

  return (
    <>
      <AuthView path={path} />
      {isSignIn && <PhoneSignInSection />}
    </>
  );
}
```

`PhoneSignInSection` เป็นคอมโพเนนต์ที่คุณเขียนเองเพื่อครอบฟอร์มเข้าสู่ระบบด้วยโทรศัพท์ โปรดดู [ตัวอย่าง nextjs-phone-login](https://github.com/neondatabase/neon-js/tree/main/examples/nextjs-phone-login) สำหรับ implementation แบบครบถ้วน

**ข้อมูล:** หากคุณยังไม่ได้ตั้งค่าคอมโพเนนต์ Managed Better Auth UI โปรดดู [เอกสารอ้างอิง UI components](https://neon.com/docs/auth/reference/ui-components) สำหรับวิธีตั้งค่า หรือ quick start สำหรับ [Next.js](https://neon.com/docs/auth/quick-start/nextjs-api-only) หรือ [React](https://neon.com/docs/auth/quick-start/react) สำหรับการสร้างฟอร์มแบบกำหนดเองแทน

## Webhook events

Phone Number plugin ใช้ webhook events สองรายการ:

- `send.otp` (blocking) ดู [ส่ง OTP ผ่านผู้ให้บริการ SMS ของคุณ](https://neon.com/docs/auth/guides/plugins/phone-number#deliver-otps-via-your-sms-provider)
- `phone_number.verified` (non-blocking) จะทำงานหลังจากผู้ใช้ยืนยันหมายเลขโทรศัพท์สำเร็จ

ดูโครงสร้าง payload, การตรวจสอบลายเซ็น และพฤติกรรม retry ได้ที่ [คู่มือ Webhooks](https://neon.com/docs/auth/guides/webhooks)

## ข้อจำกัด

- **Sign-in เท่านั้น** ผู้ใช้ต้องมีอยู่แล้วพร้อมหมายเลขโทรศัพท์ที่เชื่อมโยงและยืนยันแล้ว ไม่รองรับการสมัครสมาชิกที่เริ่มจากหมายเลขโทรศัพท์
- **ใช้ผู้ให้บริการ SMS ของคุณเอง** ไม่มีการส่ง SMS ในตัว ต้องใช้เว็บฮุก `send.otp` เพื่อส่งต่อไปยังผู้ให้บริการ SMS ของคุณ
- **ต้องใช้รูปแบบ E.164** หมายเลขโทรศัพท์ต้องตรงกับ `^\+[1-9]\d{1,14}$` (ตัวอย่างเช่น `+15551234567`) หมายเลขที่มีช่องว่าง, ขีดกลาง หรือวงเล็บจะถูกปฏิเสธ
- **ความยาว OTP กำหนดตายตัวที่ 6 หลัก** ไม่สามารถตั้งค่าได้
- **Rate limit** การเรียก endpoint `/phone-number/*` จำกัดที่ 10 requests ต่อ 60 วินาทีต่อ IP นอกเหนือจาก global rate limits ของ Managed Better Auth
- **Attempt lockout** หลังจากกรอกรหัสผิด 3 ครั้ง OTP จะถูกทำให้ใช้ไม่ได้ ต้องขอรหัสใหม่เพื่อทดลองอีกครั้ง
