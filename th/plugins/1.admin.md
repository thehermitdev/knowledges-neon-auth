> สรุป: Admin plugin ของ Managed Better Auth เปิดให้ใช้งาน Better Auth admin APIs ผ่าน Neon SDK โดยไม่ต้องตั้งค่าปลั๊กอินด้วยตนเอง ทำให้โค้ดฝั่งเซิร์ฟเวอร์สามารถสร้างผู้ใช้ กำหนด role แบนบัญชี แสดงรายการหรือเพิกถอนเซสชัน และจำลองตัวตนเป็นผู้ใช้เพื่อ support และ debugging ได้ ใช้หน้านี้เมื่อสร้าง admin dashboard หรือเครื่องมือ support ที่ต้องจัดการสถานะการยืนยันตัวตนของผู้ใช้ด้วยโค้ด Admin operations ต้องใช้ authenticated session ที่มี HTTP-only cookies และเซสชัน impersonation ถูกจำกัดไว้สูงสุด 1 ชั่วโมง

# Admin

จัดการผู้ใช้ role การแบน เซสชัน และ impersonation

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

Managed Better Auth สร้างขึ้นบน [Better Auth](https://www.better-auth.com/) และรองรับ Admin plugin APIs ผ่าน Neon SDK คุณไม่จำเป็นต้องติดตั้งหรือตั้งค่า Better Auth Admin plugin ด้วยตนเอง

Admin plugin มี APIs สำหรับจัดการผู้ใช้และสถานะการยืนยันตัวตนของผู้ใช้ โดยทั่วไปใช้สำหรับสร้างเครื่องมือภายใน (admin dashboards, เครื่องมือ support) ที่สามารถ:

- สร้างและอัปเดตผู้ใช้
- กำหนด role
- แบนและยกเลิกการแบนผู้ใช้
- แสดงรายการและเพิกถอนเซสชัน
- จำลองตัวตนเป็นผู้ใช้เพื่อ support/debugging

## ข้อกำหนดเบื้องต้น

- โปรเจ็กต์ Neon ที่ **เปิดใช้งาน Auth** แล้ว
- ผู้ใช้ที่มี role **admin** อยู่แล้วเพื่อเรียก Admin APIs

  คุณสามารถกำหนด role **admin** ให้ผู้ใช้ผ่าน Neon Console ไปที่ **Auth** → **Users** เปิดเมนูสามจุดถัดจากผู้ใช้ แล้วเลือก **Make admin**

  ![กำหนด role admin ใน Neon Console](https://neon.com/docs/auth/make-admin.png)

## ใช้ Admin ผ่านเมธอด SDK

คุณสามารถเรียกเมธอดของ Admin plugin ผ่าน Neon SDK auth client

> หากคุณยังไม่ได้ตั้งค่า Managed Better Auth ให้ทำตาม quick start สำหรับ [Next.js](https://neon.com/docs/auth/quick-start/nextjs-api-only) หรือ [React](https://neon.com/docs/auth/quick-start/react) เพื่อสร้าง `authClient`

### สร้างผู้ใช้

ใช้ Admin APIs เพื่อสร้างผู้ใช้ในนามของผู้อื่น (ตัวอย่างเช่น การ onboarding ผ่านระบบ back-office)

#### พารามิเตอร์

<details>

<summary>ดูพารามิเตอร์</summary>

| พารามิเตอร์ | Type                              | จำเป็น | หมายเหตุ                                                    |
| --------- | --------------------------------- | :------: | -------------------------------------------------------- |
| email     | string                            |     ✓    | อีเมลของผู้ใช้ใหม่                                        |
| password  | string                            |     ✓    | รหัสผ่านของผู้ใช้ใหม่                                      |
| name      | string                            |     ✓    | ชื่อที่แสดง                                                |
| role      | string \| string\[] \| undefined  |          | role ของผู้ใช้แบบไม่บังคับ (ตัวอย่างเช่น: user, admin)      |
| data      | Record\<string, any> \| undefined |          | ฟิลด์แบบกำหนดเองที่ไม่บังคับ                               |

</details>

```ts
const { data, error } = await authClient.admin.createUser({
  email: 'user@email.com',
  password: 'secure-password',
  name: 'User Name',
  role: 'user',
  data: { customUserField: 'value' },
});
```

### แสดงรายการผู้ใช้

แสดงรายการผู้ใช้พร้อมตัวเลือกสำหรับการค้นหา การกรอง การเรียงลำดับ และ pagination

#### พารามิเตอร์

<details>

<summary>ดูพารามิเตอร์</summary>

| พารามิเตอร์      | Type                                                        | จำเป็น | หมายเหตุ                                |
| -------------- | ----------------------------------------------------------- | :------: | ------------------------------------ |
| searchValue    | string \| undefined                                         |          | ค่าที่ใช้ค้นหา                         |
| searchField    | 'email' \| 'name' \| undefined                              |          | ฟิลด์ที่จะค้นหา                        |
| searchOperator | 'contains' \| 'starts\_with' \| 'ends\_with' \| undefined   |          | operator สำหรับการค้นหา                |
| limit          | number \| string \| undefined                               |          | จำนวนผู้ใช้สูงสุดที่คืน (ขนาดหน้า)       |
| offset         | number \| string \| undefined                               |          | จำนวนผู้ใช้ที่จะข้าม (pagination)       |
| sortBy         | string \| undefined                                         |          | ฟิลด์ที่ใช้เรียงลำดับ                   |
| sortDirection  | 'asc' \| 'desc' \| undefined                                |          | ทิศทางการเรียงลำดับ                    |
| filterField    | string \| undefined                                         |          | ฟิลด์ที่ใช้กรอง                         |
| filterValue    | string \| number \| boolean \| undefined                    |          | ค่าที่ใช้กรอง                          |
| filterOperator | 'eq' \| 'ne' \| 'lt' \| 'lte' \| 'gt' \| 'gte' \| undefined |          | operator สำหรับการกรอง                  |

</details>

```ts
const { data, error } = await authClient.admin.listUsers({
  query: {
    // Following parameters are optional
    searchValue: 'text to search',
    searchField: 'email',
    searchOperator: 'contains',
    limit: 10,
    offset: 0,
    sortBy: 'name',
    sortDirection: 'asc',
  },
});
```

> ใช้ `filterField`, `filterValue` และ `filterOperator` เพื่อกรองผลลัพธ์เพิ่มเติม (ตัวอย่างเช่น ตาม role เป็นต้น)

ออบเจ็กต์ `data` ประกอบด้วยรายการผู้ใช้และ metadata สำหรับ pagination:

```ts
{
  users: [/* array of user objects */],
  total: 100, // total number of users matching the query
  limit: 10,  // limit used in the query
  offset: 0   // offset used in the query
}
```

ใช้ค่า `total`, `limit` และ `offset` เพื่อทำ pagination ในเครื่องมือ admin ของคุณ

### กำหนด role ให้ผู้ใช้

กำหนด role เพื่อควบคุมว่าใครสามารถเรียก admin operations ได้

#### พารามิเตอร์

<details>

<summary>ดูพารามิเตอร์</summary>

| พารามิเตอร์ | Type                | จำเป็น | หมายเหตุ                                 |
| --------- | ------------------- | :------: | ------------------------------------- |
| userId    | string              |     ✓    | ID ของผู้ใช้ที่จะอัปเดต                  |

### แบนผู้ใช้

การแบนจะป้องกันไม่ให้ผู้ใช้เข้าสู่ระบบ คุณสามารถระบุเหตุผลและเวลาหมดอายุของการแบนได้หากต้องการ

<details>

<summary>ดูพารามิเตอร์</summary>

| พารามิเตอร์    | Type                | จำเป็น | หมายเหตุ                                                                               |
| ------------ | ------------------- | :------: | ----------------------------------------------------------------------------------- |
| userId       | string              |     ✓    | ID ของผู้ใช้ที่จะแบน                                                                  |
| banReason    | string \| undefined |          | เหตุผลของการแบน                                                                      |
| banExpiresIn | number \| undefined |          | ระยะเวลาเป็นวินาทีจนกว่าการแบนจะหมดอายุ หากไม่ระบุ การแบนจะไม่มีวันหมดอายุ             |

</details>

```ts
const { error } = await authClient.admin.banUser({
  userId: 'user-id',
  banReason: 'Policy violation',
  // banExpiresIn: 60 * 60 * 24, // optional (seconds)
});
```

## ข้อจำกัด

- Admin operations ต้องใช้ authenticated session (HTTP-only cookies) ซึ่งหมายความว่าเครื่องมือ admin ของคุณต้องทำงานบนไซต์เดียวกันที่สามารถส่งคุกกี้เหล่านั้นไปยัง Managed Better Auth API ได้
- เซสชัน impersonation ถูกจำกัดเวลาโดยตั้งใจ โดยมีอายุเท่ากับระยะเวลาของ browser session ที่ active หรือสูงสุด 1 ชั่วโมง การออกแบบนี้ช่วยลดความเสี่ยงด้านความปลอดภัยที่เกี่ยวข้องกับ impersonation ที่มีอายุยาวนาน
