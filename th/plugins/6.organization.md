> สรุป: Organization plugin ของ Managed Better Auth เพิ่มความสามารถด้าน multi-tenancy ให้แอปที่สร้างบน Better Auth โดยแต่ละ tenant สามารถใช้บรานช์ Neon ร่วมกันพร้อมการควบคุมการเข้าถึงตาม role (owner, admin และ member) ใช้เมื่อแอปของคุณต้องการ workspace หรือการแยก tenant พร้อมเวิร์กโฟลว์ invitation, membership limit ที่ตั้งค่าได้ และการควบคุมเปิด/ปิดต่อบรานช์ผ่าน Neon Console หรือ API ปลั๊กอินมีเมธอด authClient.organization สำหรับสร้าง แสดงรายการ และลบ organization, เชิญและนำ member ออก รวมถึงตรวจสอบสิทธิ์ของ role ฝั่ง client

# Organization

จัดการ organization แบบ multi-tenant, member และ invitation

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

Managed Better Auth สร้างขึ้นบน [Better Auth](https://www.better-auth.com/) และมาพร้อม Organization plugin ที่ตั้งค่าไว้ล่วงหน้า ทำให้แอปของคุณรองรับ multi-tenancy ได้โดยไม่ต้องตั้งค่าเพิ่มเติม

**หมายเหตุ: ฟีเจอร์ Preview**

ขณะนี้ Organization plugin อยู่ในสถานะ **Beta** และรองรับ JWT token claims แล้ว

## ทำไมจึงควรใช้ปลั๊กอินนี้?

ใช้ Organization plugin เมื่อคุณต้องการ multi-tenancy ในแอป โดยรองรับ:

- แอปแบบ multi-tenant ที่แต่ละ tenant เป็น organization
- Workspace หรือ group ที่ใช้บรานช์ Neon ร่วมกัน (ฐานข้อมูลเดียวกัน)
- การเชิญผู้ใช้และกำหนด role: owner, admin หรือ member
- การเข้าถึงตาม role: owner และ admin สามารถจัดการ organization ได้ ส่วน role member มีสิทธิ์อ่านอย่างเดียว

Better Auth ยังมีฟีเจอร์ **Teams** (กลุ่มย่อยภายใน organization) แต่ขณะนี้ฟีเจอร์ดังกล่าวยังไม่ได้เปิดใช้งานใน Managed Better Auth

## ข้อกำหนดเบื้องต้น

- โปรเจ็กต์ Neon ที่ **เปิดใช้งาน Auth** แล้ว
- ผู้ใช้ที่เข้าสู่ระบบแล้ว (organization เชื่อมโยงกับผู้ใช้)

## ตั้งค่า Organization plugin

Organization plugin เปิดใช้งานโดยค่าเริ่มต้นสำหรับแต่ละบรานช์ คุณสามารถปิดใช้งานหรือเปลี่ยนการตั้งค่าใน Console หรือผ่าน API ได้ หากปิดปลั๊กอิน ผู้ใช้และ admin ของแอปจะไม่สามารถสร้างหรือจัดการ organization และการเรียก API ที่เกี่ยวข้องกับ organization ทั้งหมดจะคืน error

**Console**

เปิดโปรเจ็กต์ของคุณใน Neon Console จากนั้นไปที่ **Auth** > **Plugins** (beta) และใช้ส่วน **Organizations** (แยกตามบรานช์) แท็บนี้ใช้งานได้เมื่อโปรเจ็กต์ของคุณใช้ Managed Better Auth ร่วมกับ **Better Auth** ส่วนการตั้งค่า Auth อื่น รวมถึง **Auth URL** จะยังอยู่ในแท็บ **Configuration** จากหน้านี้คุณสามารถปรับแต่ง:

![แท็บ Auth Plugins ใน Neon Console พร้อมการตั้งค่า Organizations](https://neon.com/docs/changelog/neon_auth_plugins_organizations.png)

- **Enable Organizations** (toggle): เปิดหรือปิด Organization plugin สำหรับบรานช์ เมื่อปิด การเรียก organization API ทั้งหมดจะถูกปิดใช้งานและคืน error
- **Limit:** จำนวน membership ของ organization รวมสูงสุด (ที่สร้าง + ที่เข้าร่วม) ต่อผู้ใช้ เมื่อถึงลิมิต ผู้ใช้จะไม่สามารถสร้าง organization ใหม่ได้ ค่าเริ่มต้น: 10
- **Membership Limit:** จำนวน member สูงสุดต่อ organization (ค่าเริ่มต้น: 100)
- **Creator role:** role ที่กำหนดให้ผู้ใช้ซึ่งสร้าง organization: **Owner** หรือ **Admin** เลือก Admin หากต้องการให้ผู้สร้าง organization มีสิทธิ์น้อยกว่า Owner (ตัวอย่างเช่น ไม่สามารถลบ organization หรือเปลี่ยน owner ได้)
- **Send Invitation Email** (toggle): เมื่อเปิด ผู้ใช้ที่ได้รับเชิญจะได้รับอีเมลพร้อมลิงก์ยอมรับ invitation โดยต้องเปิด **Verify email at signup** ในการตั้งค่า Authentication ด้วย การยอมรับ invitation ต้องใช้ [`AuthView` component](https://neon.com/docs/auth/reference/ui-components#core-components) หรือ custom route ที่รองรับ `/auth/accept-invitation?invitationId=<INV_ID>` ในแอปของคุณ เมื่อปิด จะไม่มีการส่งอีเมล และคุณต้องจัดการ invitation ในแอปเอง (ตัวอย่างเช่น ผ่าน [invitation ID](https://neon.com/docs/auth/guides/plugins/organization#accept-invitation) หรือ [รายการ invitation ของผู้ใช้](https://neon.com/docs/auth/guides/plugins/organization#list-user-invitations))

**API**

คุณยังสามารถตั้งค่าปลั๊กอินผ่าน [Neon API](https://neon.com/docs/reference/api) ได้ โดยใช้ API key ของคุณใน header `Authorization`

**ดูการตั้งค่าปลั๊กอินปัจจุบัน (รวม organization):**

```bash
curl -X GET \
  'https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth/plugins' \
  -H 'Accept: application/json' \
  -H 'Authorization: Bearer $NEON_API_KEY'
```

ตัวอย่าง response (ตัดมาเฉพาะออบเจ็กต์ `organization`):

```json
{
  "organization": {
    "enabled": true,
    "organization_limit": 10,
    "membership_limit": 100,
    "creator_role": "owner",
    "send_invitation_email": false
  }
}
```

Response แบบเต็มจะรวมการตั้งค่าปลั๊กอินอื่นด้วย (email provider, OAuth เป็นต้น) โดย `creator_role` เป็นได้ทั้ง `owner` หรือ `admin`

**อัปเดต Organization plugin:**

ส่งเฉพาะฟิลด์ที่คุณต้องการเปลี่ยน โดยทุกฟิลด์ใน request body เป็นตัวเลือก

```bash
curl -X PATCH \
  'https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth/plugins/organization' \
  -H 'Accept: application/json' \
  -H 'Authorization: Bearer $NEON_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "enabled": true,
    "organization_limit": 10,
    "membership_limit": 100,
    "creator_role": "owner",
    "send_invitation_email": false
  }'
```

ตัวอย่าง response:

```json
{
  "enabled": true,
  "organization_limit": 10,
  "membership_limit": 100,
  "creator_role": "owner",
  "send_invitation_email": false
}
```

### เอกสารอ้างอิงฟิลด์ API

| Field                   | Type                        | คำอธิบาย                                                                                                                              |
| :---------------------- | :-------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| `enabled`               | boolean                     | เปิดหรือปิด Organization plugin สำหรับบรานช์ เมื่อเป็น false การเรียก organization API ทั้งหมดจะคืน error                          |
| `organization_limit`    | number (≥ 1)                | จำนวน membership ของ organization รวมสูงสุด (ที่สร้าง + ที่เข้าร่วม) ต่อผู้ใช้ เมื่อถึงลิมิต ผู้ใช้จะไม่สามารถสร้าง organization ใหม่ได้ ค่าเริ่มต้น: 10 |
| `membership_limit`      | number (≥ 1)                | จำนวน member สูงสุดต่อ organization ค่าเริ่มต้น: 100                                                                                 |
| `creator_role`          | string (`owner` \| `admin`) | role สำหรับผู้ใช้ที่สร้าง organization โดย Owner มีสิทธิ์ควบคุมเต็มรูปแบบ ส่วน Admin ไม่สามารถลบ organization หรือเปลี่ยน owner ได้ |
| `send_invitation_email` | boolean                     | เมื่อเป็น true ผู้ใช้ที่ได้รับเชิญจะได้รับอีเมลพร้อมลิงก์ยอมรับ ต้องยืนยันอีเมลตอนสมัครสมาชิก ค่าเริ่มต้น: false                     |

## Organizations

ใช้เมธอดต่อไปนี้เพื่อจัดการ lifecycle ของ organization

### สร้าง organization

สร้าง organization ใหม่ ผู้ใช้ที่สร้างจะกลายเป็น **Owner** โดยอัตโนมัติ

<details>

<summary>ดูพารามิเตอร์</summary>

| พารามิเตอร์                    | Type                               | จำเป็น | หมายเหตุ                                                             |
| :---------------------------- | :--------------------------------- | :------: | :-------------------------------------------------------------------- |
| name                          | string                             |     ✓    | ชื่อที่แสดงของ organization                                           |
| slug                          | string                             |     ✓    | identifier ที่เหมาะสำหรับใช้ใน URL                                   |
| logo                          | string \| undefined                |          | URL ของรูปโลโก้สำหรับ organization แบบไม่บังคับ                      |
| metadata                      | `Record<string, any>` \| undefined |          | JSON metadata สำหรับ organization แบบไม่บังคับ                       |
| userId                        | string \| undefined                |          | ID ผู้ใช้ของผู้สร้าง organization                                     |
| keepCurrentActiveOrganization | boolean \| undefined               |          | หากเป็น `true` จะไม่เปลี่ยน active session ไปยัง organization ใหม่   |

```ts
const { data, error } = await authClient.organization.create({
  name: 'My Organization',
  slug: 'my-org',
  logo: 'https://example.com/logo.png',
  metadata: { plan: 'pro' },
  keepCurrentActiveOrganization: false,
});
```

### แสดงรายการ organization

<details>

<summary>ดูพารามิเตอร์</summary>

เมธอดนี้ไม่รับพารามิเตอร์ใดๆ

</details>

```ts
const { data, error } = await authClient.organization.list();
```

ในคอมโพเนนต์ React คุณสามารถใช้ hook `useListOrganizations` เพื่อดึงและแสดง organization:

```tsx
import { authClient } from './auth';

export default function OrganizationList() {
  const { data: organizations } = authClient.useListOrganizations();
  return (
    <div>
      {organizations?.map((org) => (
        <p>{org.name}</p>
      ))}
    </div>
  );
}
```

```tsx
export default function ActiveOrganization() {

      <p>Members: {organization?.members.length}</p>
    </div>
  );
}
```

## Invitations

จัดการ invitation เพื่อเข้าร่วม organization

**หมายเหตุ: อีเมล Invitation**

รองรับอีเมล invitation เมื่อเปิด [**Send Invitation Email**](https://neon.com/docs/auth/guides/plugins/organization#configure-the-organization-plugin) ในการตั้งค่า organization ซึ่งต้องเปิด **Verify email at signup** ในการตั้งค่า Authentication ด้วย การยอมรับ invitation ทางอีเมลต้องใช้ [`AuthView` component](https://neon.com/docs/auth/reference/ui-components#core-components) หรือ custom route ที่รองรับ `/auth/accept-invitation?invitationId=<INV_ID>` ในแอปของคุณ

เมื่อปิด toggle อีเมล ให้จัดการ invitation ในแอปของคุณผ่าน [invitation ID](https://neon.com/docs/auth/guides/plugins/organization#accept-invitation) หรือ [รายการ invitation ของผู้ใช้](https://neon.com/docs/auth/guides/plugins/organization#list-user-invitations)

### เชิญ member

ส่ง invitation ให้ผู้ใช้

<details>

<summary>ดูพารามิเตอร์</summary>

| พารามิเตอร์     | Type                 | จำเป็น | หมายเหตุ                                                   |
| :------------- | :------------------- | :------: | :-------------------------------------------------- |
| email          | string               |     ✓    | อีเมลที่จะเชิญ                                            |

## การควบคุมการเข้าถึง

Organization plugin มีระบบ Role-Based Access Control (RBAC)

| Role       | สิทธิ์                                                                                                                                    |
| :--------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| **Owner**  | ควบคุมได้เต็มรูปแบบ สามารถลบ organization และจัดการ role ทั้งหมด ผู้ใช้ที่สร้าง organization จะได้รับ role นี้โดยอัตโนมัติ              |
| **Admin**  | สามารถเชิญ member, อัปเดต role และจัดการการตั้งค่า organization แต่ไม่สามารถลบ organization ได้                                          |
| **Member** | มีสิทธิ์อ่านข้อมูล organization เท่านั้น ไม่สามารถจัดการ member คนอื่นได้                                                                   |

คุณสามารถตรวจสอบสิทธิ์ฝั่ง client ด้วย `checkRolePermission`:

```ts
const canDelete = authClient.organization.checkRolePermission({
  permission: {
    organization: ['delete'],
  },
  role: 'admin', // returns false, admins cannot delete orgs
});
// console.log(canDelete); // false
```

## ข้อจำกัด

เนื่องจาก Managed Better Auth เป็น managed service ฟีเจอร์ Better Auth บางอย่างจึงยังไม่รองรับในขณะนี้:

- **Teams:** ฟีเจอร์ย่อย Teams ยังไม่ได้เปิดใช้งาน
- **Hooks:** ไม่รองรับ hooks ฝั่งเซิร์ฟเวอร์ (ตัวอย่างเช่น `beforeCreateOrganization`)
- **Custom Permissions:** ขณะนี้คุณไม่สามารถกำหนด custom roles หรือแก้ไขสิทธิ์เริ่มต้นได้
- **Dynamic Access Control:** ยังไม่เปิดใช้งานการสร้าง role แบบ dynamic ผ่าน API

ตรวจสอบความคืบหน้าของฟีเจอร์เหล่านี้ได้ที่ [โรดแมป Managed Better Auth](https://neon.com/docs/auth/roadmap)
