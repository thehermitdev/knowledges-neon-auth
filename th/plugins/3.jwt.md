> สรุป: JWT plugin ของ Managed Better Auth ช่วยให้บริการ backend, เครื่องมือ CLI และ API request ข้ามโดเมนสามารถดึง JSON Web Token แบบ raw ผ่าน `authClient.token()` หรือ response header `set-auth-jwt` แทนการพึ่งพา HTTP-only session cookies โทเค็นจะถูกลงลายเซ็นด้วย EdDSA (Ed25519) และหมดอายุใน 15 นาที โดยตรวจสอบได้ผ่าน JWKS endpoint ที่ `<YOUR_NEON_AUTH_URL>/.well-known/jwks.json` ปลั๊กอินนี้ไม่ใช่ตัวแทนของการจัดการเซสชันในแอปที่ทำงานบนเบราว์เซอร์ และยังไม่รองรับ custom JWT claims

# JWT

ยืนยันตัวตนด้วย JSON Web Tokens (JWT) สำหรับบริการภายนอก

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

Managed Better Auth สร้างขึ้นบน [Better Auth](https://www.better-auth.com/) และรองรับ JWT plugin APIs ผ่าน Neon SDK คุณไม่จำเป็นต้องติดตั้งหรือตั้งค่า Better Auth JWT plugin ด้วยตนเอง

แม้ Managed Better Auth จะใช้ **secure, HTTP‑only cookies** (sessions) เป็นหลักสำหรับการยืนยันตัวตนบนเบราว์เซอร์ แต่บางกรณีจำเป็นต้องใช้ raw token ซึ่ง JWT plugin มีประโยชน์เป็นพิเศษในกรณีเหล่านี้:

- **Microservices:** แชร์ข้อมูลระบุตัวตนระหว่างบริการ backend
- **โดเมน frontend และ backend แยกกัน:** ยืนยันตัวตนของ API request จากโดเมนที่แตกต่างจากแอปพลิเคชันหลัก
- **เครื่องมือ CLI:** เปิดใช้การยืนยันตัวตนจาก command-line interface

**คำเตือน: Sessions เทียบกับ JWTs**

ปลั๊กอินนี้ **ไม่ใช่** ตัวแทนของการจัดการเซสชันในเว็บแอปพลิเคชัน สำหรับแอปบนเบราว์เซอร์ทั่วไป (Next.js, React, Vue เป็นต้น) ให้ใช้กลไก session cookie เริ่มต้นที่ `authClient.signIn` และ `authClient.getSession` มีให้

ใช้ JWT เฉพาะเมื่อคุณจำเป็นต้อง authorize request ไปยังบริการที่ไม่สามารถเข้าถึง cookie jar ของเบราว์เซอร์ได้

## ดึง Token

คุณสามารถดึง JWT สำหรับผู้ใช้ที่กำลังเข้าสู่ระบบอยู่ผ่าน Neon SDK

### ใช้เมธอด SDK

หากต้องการดึง raw token string ให้ใช้เมธอด `authClient.token()` วิธีนี้เป็นแนวทางที่แนะนำสำหรับแอป client ที่ต้องแนบ token เข้ากับ API request header ด้วยตนเอง

```ts filename="src/get-token.ts"
import { authClient } from './auth';

export async function getJwtToken() {
  const { data, error } = await authClient.token();

  if (error) throw error;

  // The token string (for example, "eyJhbGciOiJFZ...")
  return data.token;
}
```

หากแอปของคุณถูกให้บริการจาก origin ที่แตกต่างจาก Managed Better Auth URL (ตัวอย่างเช่น Vite หรือ SPA dev server บน `localhost` ที่เชื่อมต่อกับ auth บน `*.neon.tech`) ให้ตั้งค่า auth client ให้ส่ง session cookie ไปกับ cross-origin request ไม่เช่นนั้น `authClient.token()` จะคืน `data.token` เป็น `undefined` และการเรียก API ของคุณจะล้มเหลวด้วย 401

```ts filename="src/auth.ts"
export const authClient = createAuthClient(NEON_AUTH_URL, {
  fetchOptions: { credentials: 'include' },
});
```

การตั้งค่าแบบ cross-domain มีข้อจำกัดเพิ่มเติม โดยเฉพาะ Safari ITP ที่บล็อก third-party cookies ซึ่งมี workaround เช่น reverse proxy หรือ shared parent domain ดู [Better Auth: Safari, ITP, and Cross-Domain Setups](https://www.better-auth.com/docs/concepts/cookies#safari-itp-and-cross-domain-setups)

### ใช้ session header

เมื่อคุณเรียก `authClient.getSession()` Managed Better Auth จะใส่ JWT ใน response headers ให้อัตโนมัติ หากคุณใช้ custom fetcher หรือต้องการดัก token ทันทีหลังตรวจสอบเซสชัน:

```ts
await authClient.getSession({
  fetchOptions: {
    onSuccess: (ctx) => {
      const jwt = ctx.response.headers.get('set-auth-jwt');
      console.log('JWT:', jwt);
    },
  },
});
```

### ตัวอย่าง JWT payload ที่ decode แล้ว

JWT payload ที่ decode แล้วโดยทั่วไปจะมีลักษณะดังนี้:

```json
{
  "iat": 1766320685,
  "name": "User Name",
  "email": "user@email.com",
  "emailVerified": false,
  "image": null,
  "createdAt": "2025-12-20T11:04:41.437Z",
  "updatedAt": "2025-12-20T11:04:41.437Z",
  "role": "authenticated",
  "banned": false,
  "banReason": null,
  "banExpires": null,
  "id": "860dc360-609f-4b7d-9e70-ec93fe6414d3",

  "iss": "<YOUR_NEON_AUTH_URL_ORIGIN>",

```

## ตรวจสอบ token

ในการตรวจสอบความถูกต้องของ JWT คุณต้องตรวจสอบลายเซ็นด้วย public keys ที่ JWKS (JSON Web Key Set) มีให้

Managed Better Auth เปิด public JWKS endpoint ที่มี public keys ซึ่งจำเป็นสำหรับตรวจสอบลายเซ็นของ JWT

### JWKS endpoint

JWKS endpoint ของ Managed Better Auth อยู่ที่:

```
<YOUR_NEON_AUTH_URL>/.well-known/jwks.json
```

หากคุณตรวจสอบ Neon Auth JWT ภายใน [Neon Functions](https://neon.com/docs/compute/functions/overview) แพลตฟอร์มจะ inject `NEON_AUTH_BASE_URL` และ `NEON_AUTH_JWKS_URL` เมื่อมีการ provision Neon Auth บนบรานช์ ให้ใช้ `NEON_AUTH_JWKS_URL` โดยตรงแทนการสร้างค่านี้เอง ดู [Functions environment variables](https://neon.com/docs/compute/functions/environment-variables#neon-injected-variables)

### ตัวอย่างการตรวจสอบ

ตัวอย่างต่อไปนี้แสดงวิธีตรวจสอบ Managed Better Auth JWT ในหลายภาษาโปรแกรม ไม่ว่าคุณจะใช้ภาษาใด กระบวนการจะเหมือนกัน: ดึง JWKS จาก endpoint ที่ให้มา แล้วใช้เพื่อตรวจสอบลายเซ็นและ claims ของ token หากไม่มีภาษาที่คุณต้องการในรายการนี้ คุณสามารถนำหลักการเดียวกันไปใช้ใน environment ของคุณได้

**ข้อมูล: ความพร้อมสำหรับ Production**

ตัวอย่างต่อไปนี้มีไว้เพื่อใช้อ้างอิงเท่านั้น และไม่รับประกันว่าพร้อมสำหรับ production โปรดทำ caching, error handling และแนวทางปฏิบัติด้านความปลอดภัยที่เหมาะสมตามที่แอปพลิเคชันของคุณต้องการ

**Node.js**

1. ติดตั้งไลบรารี:

   ```bash
   npm install jose
   ```

2. ใช้โค้ดตัวอย่างต่อไปนี้เป็นข้อมูลอ้างอิงในการตรวจสอบ JWT:

   ```ts
   import { jwtVerify, createRemoteJWKSet } from 'jose';

   const NEON_JWKS_URL = `${process.env.NEON_AUTH_BASE_URL}/.well-known/jwks.json`;
   const JWKS = createRemoteJWKSet(new URL(NEON_JWKS_URL));

   export async function validateNeonToken(token: string) {
       try {
           const { payload } = await jwtVerify(token, JWKS, {
               issuer: new URL(process.env.NEON_AUTH_BASE_URL!).origin
           });

           return payload;
       } catch (error) {
           console.error('Token validation failed:', error);
           return null;
       }
   }

   validateNeonToken(<YOUR_JWT_TOKEN>).then((payload) => {
       console.log('Token is valid. Payload:', payload);
   }).catch(() => {
       console.log('Token is invalid.');
   });
   ```

   > แทนที่ `<YOUR_JWT_TOKEN>` ด้วย JWT token จริงที่คุณต้องการตรวจสอบ

**Python**

1. ติดตั้งไลบรารี:

   ```bash
   pip install PyJWT requests cryptography
   ```

2. ใช้โค้ดตัวอย่างต่อไปนี้เป็นข้อมูลอ้างอิงในการตรวจสอบ JWT:

   ```py
   import base64
   import os
   from urllib.parse import urlparse

   import jwt
   import requests
   from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey
   from jwt import PyJWTError

   NEON_AUTH_BASE_URL = os.environ.get("NEON_AUTH_BASE_URL", "")
   NEON_JWKS_URL = f"{NEON_AUTH_BASE_URL}/.well-known/jwks.json"
   parsed = urlparse(NEON_AUTH_BASE_URL)
   ORIGIN = f"{parsed.scheme}://{parsed.netloc}"

   def get_jwks():
       response = requests.get(NEON_JWKS_URL)
       response.raise_for_status()
       return response.json()

   def get_signing_key(token, jwks):
       unverified_header = jwt.get_unverified_header(token)
       kid = unverified_header["kid"]

       for jwk in jwks["keys"]:
           if jwk["kid"] == kid:
               x = jwk["x"]
               public_key_bytes = base64.urlsafe_b64decode(x + "==")
               return Ed25519PublicKey.from_public_bytes(public_key_bytes)

       raise ValueError("Matching JWK not found")

   def validate_neon_token(token: str):
       try:
           jwks = get_jwks()
           signing_key = get_signing_key(token, jwks)

           payload = jwt.decode(
               token, key=signing_key, algorithms=["EdDSA"], issuer=ORIGIN, audience=ORIGIN
           )

           return payload

       except PyJWTError as error:
           print("Token validation failed:", error)
           return None
       except Exception as error:
           print("Unexpected error:", error)
           return None


   payload = validate_neon_token("<YOUR_JWT_TOKEN>")

   if payload:
       print("Token is valid. Payload:", payload)
   else:
       print("Token is invalid.")
   ```

   > แทนที่ `<YOUR_JWT_TOKEN>` ด้วย JWT token จริงที่คุณต้องการตรวจสอบ

**Go**

1. ติดตั้งไลบรารี:

   ```bash
   go get github.com/golang-jwt/jwt/v5
   go get github.com/MicahParks/keyfunc/v3
   ```

2. ใช้โค้ดตัวอย่างต่อไปนี้เป็นข้อมูลอ้างอิงในการตรวจสอบ JWT:

   ```go
   package main

   import (
       "fmt"
       "log"
       "net/url"
       "os"

       "github.com/MicahParks/keyfunc/v3"
       "github.com/golang-jwt/jwt/v5"
   )

   func ValidateNeonToken(tokenString string) (jwt.MapClaims, error) {
       baseURL := os.Getenv("NEON_AUTH_BASE_URL")
       if baseURL == "" {
           return nil, fmt.Errorf("NEON_AUTH_BASE_URL is not set")
       }

       jwksURL := fmt.Sprintf("%s/.well-known/jwks.json", baseURL)

       u, err := url.Parse(baseURL)
       if err != nil {
           return nil, fmt.Errorf("failed to parse base URL: %w", err)
       }
       expectedIssuer := fmt.Sprintf("%s://%s", u.Scheme, u.Host)

       jwks, err := keyfunc.NewDefault([]string{jwksURL})
       if err != nil {
           return nil, fmt.Errorf("failed to create JWKS from resource at %s: %w", jwksURL, err)
       }

       token, err := jwt.Parse(tokenString, func(token *jwt.Token) (interface{}, error) {
           return jwks.Keyfunc(token)
       },
           jwt.WithIssuer(expectedIssuer),
           jwt.WithValidMethods([]string{"EdDSA"}),
       )

       if err != nil {
           return nil, err
       }

       if claims, ok := token.Claims.(jwt.MapClaims); ok && token.Valid {
           return claims, nil
       }

       return nil, fmt.Errorf("invalid token claims")
   }

   func main() {
       tokenString := "<YOUR_JWT_TOKEN>"

       claims, err := ValidateNeonToken(tokenString)
       if err != nil {
           log.Printf("Token validation failed: %v\n", err)
           return
       }

       fmt.Printf("Token is valid. Payload: %+v\n", claims)
   }
   ```

   > แทนที่ `<YOUR_JWT_TOKEN>` ด้วย JWT token จริงที่คุณต้องการตรวจสอบ

## ข้อจำกัด

เนื่องจาก Managed Better Auth เป็น managed service การตั้งค่าฝั่งเซิร์ฟเวอร์บางอย่างที่มีใน Better Auth แบบ standalone จะถูก Neon ตั้งค่าไว้ล่วงหน้าและไม่สามารถเปลี่ยนได้:

- **อัลกอริทึมการลงลายเซ็น:** Managed Better Auth ใช้ **EdDSA (Ed25519)** โดยค่าเริ่มต้นเพื่อความปลอดภัยและประสิทธิภาพสูง ตรวจสอบให้แน่ใจว่าไลบรารีสำหรับ verification ของคุณรองรับอัลกอริทึมนี้
- **การหมดอายุ:** Tokens หมดอายุใน **15 นาที** (access tokens) คุณควรทำ logic สำหรับ refresh token ด้วย `authClient.token()` เมื่อ token หมดอายุ
- **Custom claims:** ปัจจุบัน JWT payload มีข้อมูลผู้ใช้เริ่มต้น ยังไม่รองรับ custom claims ในขณะนี้

## การแก้ไขปัญหา

### Token ถูกปฏิเสธ

หาก token ถูกปฏิเสธระหว่างการตรวจสอบ ให้ตรวจสอบรายการต่อไปนี้:

1. ตรวจสอบว่าคุณใช้ JWKS endpoint ที่ถูกต้องสำหรับ Managed Better Auth instance ของคุณ issuer ของ token ต้องตรงกับ origin ของ Managed Better Auth URL (ตัวอย่างเช่น หาก Managed Better Auth URL คือ `https://ep-xx.aws.neon.tech/neondb/auth` issuer ควรเป็น `https://ep-xx.aws.neon.tech`)
2. ยืนยันว่าไลบรารี verification ของคุณรองรับ **EdDSA** (Ed25519)
3. ตรวจสอบว่า token ยังไม่หมดอายุ
4. ตรวจสอบว่า `kid` ใน JWT header ตรงกับ key รายการใดรายการหนึ่งใน JWKS response หากไม่ตรง ให้ดึง keys ล่าสุดจาก JWKS endpoint
