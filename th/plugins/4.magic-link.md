> ดัชนีเอกสาร Neon ฉบับเต็ม: https://neon.com/docs/llms.txt

> สรุป: Magic Link เป็นปลั๊กอินของ Managed Better Auth ที่ช่วยให้ผู้ใช้เข้าสู่ระบบโดยไม่ใช้รหัสผ่าน ด้วยการคลิกลิงก์ที่มีเวลาจำกัดซึ่งส่งไปยังอีเมล โดยสามารถกำหนดเวลาหมดอายุได้ตั้งแต่ 5 ถึง 1440 นาที ใช้หน้านี้เมื่อต้องการเพิ่มการยืนยันตัวตนผ่านอีเมลแบบไม่ใช้รหัสผ่านให้กับโปรเจ็กต์ที่เปิดใช้งาน Managed Better Auth อยู่แล้ว โดยใช้เมธอด `signIn.magicLink()` ของ Neon SDK หรือ prop `magicLink` บน `NeonAuthUIProvider` ปลั๊กอินยังรองรับ webhook event (`send.magic_link`) เพื่อข้าม mailer ในตัวและส่งลิงก์ผ่านผู้ให้บริการอีเมลแบบกำหนดเอง

# Magic Link

เข้าสู่ระบบแบบไม่ใช้รหัสผ่านผ่านเมจิกลิงก์ทางอีเมล

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

Managed Better Auth สร้างขึ้นบน [Better Auth](https://www.better-auth.com/) และรองรับ API ของปลั๊กอิน [Magic Link](https://www.better-auth.com/docs/plugins/magic-link) อย่างเต็มรูปแบบผ่าน Neon SDK คุณไม่จำเป็นต้องติดตั้งหรือตั้งค่า Better Auth Magic Link plugin ด้วยตนเอง

Magic Link ช่วยให้ผู้ใช้เข้าสู่ระบบได้ด้วยการคลิกลิงก์ที่ส่งไปยังอีเมล โดยไม่ต้องใช้รหัสผ่าน โฟลว์ทำงานดังนี้:

1. ผู้ใช้กรอกอีเมลของตน
2. Managed Better Auth ส่งอีเมลที่มีลิงก์เฉพาะซึ่งมีเวลาจำกัด
3. ผู้ใช้คลิกลิงก์ ซึ่งจะตรวจสอบ token, สร้างเซสชัน และ redirect ผู้ใช้ไปยังแอปของคุณ

## ข้อกำหนดเบื้องต้น

- โปรเจ็กต์ Neon ที่ **เปิดใช้งาน Auth** แล้ว
- **เปิดใช้งาน Magic Link plugin** (ดู [เปิดใช้งาน Magic Link](https://neon.com/docs/auth/guides/plugins/magic-link#enable-magic-link) ด้านล่าง)

## เปิดใช้งาน Magic Link

**Console**

1. เปิด [Neon Console](https://console.neon.tech)
2. เลือกโปรเจ็กต์ของคุณแล้วไปที่ **Auth** > **Plugins**
3. เปิด toggle **Magic Link**
4. ตั้งค่าตัวเลือก:
   - **Link Expiration** (5-1440 นาที, ค่าเริ่มต้น: 5) กำหนดว่าเมจิกลิงก์จะยังใช้งานได้นานเท่าใด
   - **Allow New User Registration** กำหนดว่าสามารถใช้เมจิกลิงก์เพื่อสร้างบัญชีใหม่ได้หรือไม่ เมื่อปิด เมจิกลิงก์จะใช้งานได้เฉพาะกับผู้ใช้ที่มีอยู่แล้ว

![แท็บ Auth Plugins ใน Neon Console พร้อมการตั้งค่า Magic Link](https://neon.com/docs/auth/neon_auth_plugins_magic_link.png)

**API**

ส่ง request แบบ `PATCH` เพื่อตั้งค่า Magic Link plugin ฟิลด์ทั้งหมดใน request body เป็นตัวเลือก ส่งเฉพาะฟิลด์ที่คุณต้องการเปลี่ยน

```bash
curl -X PATCH \
  "https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth/plugins/magic-link" \
  -H "Authorization: Bearer $NEON_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "enabled": true,
    "expires_in": 5,
    "disable_sign_up": false
  }'
```

| Field             | Type    | Default | คำอธิบาย                                              |
| ----------------- | ------- | ------- | ----------------------------------------------------- |
| `enabled`         | boolean | `false` | ระบุว่า Magic Link plugin เปิดใช้งานอยู่หรือไม่         |
| `expires_in`      | integer | `5`     | จำนวนนาทีก่อนเมจิกลิงก์หมดอายุ (5-1440)               |
| `disable_sign_up` | boolean | `false` | เมื่อเป็น `true` เมจิกลิงก์จะใช้ได้เฉพาะกับผู้ใช้เดิม     |

## ใช้ Magic Link กับเมธอด SDK

สร้างโฟลว์เมจิกลิงก์แบบกำหนดเองด้วย [Neon SDK](https://neon.com/docs/reference/javascript-sdk) เรียก `signIn.magicLink()` พร้อมอีเมลของผู้ใช้และ callback URL จากนั้น Managed Better Auth จะส่งอีเมลและ redirect ผู้ใช้ไปยัง `callbackURL` หลังจากผู้ใช้คลิกลิงก์

```ts filename="src/send-magic-link.ts"
import { authClient } from '@/lib/auth/client';

export async function sendMagicLink(email: string) {
  const { error } = await authClient.signIn.magicLink({
    email,
    callbackURL: '/dashboard',
  });

  if (error) throw error;
}
```

หลังจากเรียก `signIn.magicLink()` ให้แสดงข้อความ "ตรวจสอบอีเมลของคุณ" แก่ผู้ใช้ สำหรับตัวอย่างที่ใช้งานได้ครบถ้วนซึ่งมี error handling, resend และ state management ดู [แอปตัวอย่าง magic link](https://github.com/neondatabase/neon-js/tree/main/examples/neon-auth-magic-link-example) ใน repository neon-js

## ใช้ Magic Link กับคอมโพเนนต์ UI

หากคุณใช้คอมโพเนนต์ Managed Better Auth UI อยู่แล้ว คุณสามารถเปิดใช้งาน Magic Link ด้วย prop เดียวแทนการสร้างฟอร์มแบบกำหนดเอง โดยส่ง prop `magicLink` ให้ `NeonAuthUIProvider`:

```tsx filename="app/layout.tsx"
'use client';

import { authClient } from '@/lib/auth/client';
import { NeonAuthUIProvider } from '@neondatabase/auth-ui';
import '@neondatabase/auth-ui/css';
import './globals.css';

export default function RootLayout({ children }: Readonly<{ children: React.ReactNode }>) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body className={'antialiased'}>
        <NeonAuthUIProvider
          authClient={authClient}
          magicLink
        >
          {children}
        </NeonAuthUIProvider>
      </body>
    </html>
  );
}
```

ตอนนี้ผู้ใช้สามารถเข้าสู่ระบบด้วยเมจิกลิงก์ได้โดยเลือกตัวเลือกนี้บนหน้าจอเข้าสู่ระบบและกรอกอีเมลของตน

> หากคุณยังไม่ได้ตั้งค่าคอมโพเนนต์ Managed Better Auth UI โปรดดู [เอกสารอ้างอิง UI components](https://neon.com/docs/auth/reference/ui-components) สำหรับวิธีตั้งค่า หรือ quick start สำหรับ [Next.js](https://neon.com/docs/auth/quick-start/nextjs-api-only) หรือ [React](https://neon.com/docs/auth/quick-start/react) สำหรับการสร้างฟอร์มแบบกำหนดเองแทน

## เว็บฮุก

หากคุณ subscribe event `send.magic_link` Managed Better Auth จะข้ามอีเมลในตัวและเรียก webhook ของคุณแทน พร้อมส่ง `link_type: "sign-in"` ใน payload โดย handler ของคุณมีหน้าที่ส่งลิงก์ (ตัวอย่างเช่น ผ่านเทมเพลตอีเมลแบบกำหนดเองหรือ SMS)

ดูรายละเอียดการตั้งค่าและรูปแบบ payload ได้ที่ [คู่มือ Webhooks](https://neon.com/docs/auth/guides/webhooks)

## การตั้งค่าผู้ให้บริการอีเมล

สำหรับสภาพแวดล้อม production เราแนะนำอย่างยิ่งให้ใช้ผู้ให้บริการอีเมลโดยเฉพาะ ส่วน shared SMTP เริ่มต้นควรใช้เฉพาะระหว่าง development เท่านั้น ดูวิธีตั้งค่าที่ [คู่มือการตั้งค่าผู้ให้บริการอีเมล](https://neon.com/docs/auth/production-checklist#email-provider)
