## ตั้งค่า environment variables

สร้างไฟล์ `.env.local` ที่รูทของโปรเจ็กต์ แล้วเพิ่ม Auth URL และ cookie secret:

**หมายเหตุ:** แทนที่ Auth URL ด้วย Auth URL จริงจาก Neon Console สร้าง cookie secret ที่ปลอดภัยด้วย `openssl rand -base64 32`

```bash filename=".env.local"
NEON_AUTH_BASE_URL=https://ep-xxx.neonauth.us-east-1.aws.neon.tech/neondb/auth
NEON_AUTH_COOKIE_SECRET=your-secret-at-least-32-characters-long
```

## สร้าง auth server instance

สร้าง auth instance แบบรวมศูนย์ใน `lib/auth/server.ts` โดย instance เดียวนี้จะมีฟังก์ชันการยืนยันตัวตนฝั่งเซิร์ฟเวอร์ทั้งหมด:

- `.handler()` สำหรับ API routes
- `.middleware()` สำหรับป้องกัน routes
- `.getSession()` และเมธอดฝั่งเซิร์ฟเวอร์ทั้งหมดของ Better Auth

ดูเอกสาร API ฉบับสมบูรณ์ (logging, cookies และ upstream errors) ได้ที่ [เอกสารอ้างอิง Next.js Server SDK](https://neon.com/docs/auth/reference/nextjs-server)

**หมายเหตุ: Server logging**

โดยค่าเริ่มต้น SDK จะบันทึกข้อความ **`error`** และ **`warn`** แบบมีโครงสร้างลงใน **`console`** (`logLevel: 'warn'`) ซึ่งช่วยในการตรวจสอบเมื่อ auth proxy หรือ upstream Auth URL ถูกตั้งค่าผิด กำหนด **`logLevel: 'silent'`** เพื่อปิด logging ของ Managed Better Auth หรือกำหนด **`logLevel: 'debug'`** เพื่อดูรายละเอียดเพิ่มเติม ดู [Server logging](https://neon.com/docs/auth/reference/nextjs-server#server-logging) ในเอกสารอ้างอิง

```typescript filename="lib/auth/server.ts"
import { createNeonAuth } from '@neondatabase/auth/next/server';

export const auth = createNeonAuth({
  baseUrl: process.env.NEON_AUTH_BASE_URL!,
  cookies: {
    secret: process.env.NEON_AUTH_COOKIE_SECRET!,
    // sessionDataTtl: 300, // optional session_data cache TTL in seconds (default: 300)
  },
  // logLevel: 'silent', // disable Managed Better Auth logging
  // logLevel: 'debug',  // verbose proxy/upstream logging
});
```

## ตั้งค่า auth API routes

สร้าง API route handler ที่ทำหน้าที่ proxy คำขอการยืนยันตัวตน API ทั้งหมดของ Managed Better Auth จะถูกส่งผ่าน handler นี้ สร้างไฟล์ route ภายในไดเรกทอรี `/api/auth/[...path]`:

ใน `app/api/auth/[...path]/route.ts`:

```typescript filename="app/api/auth/[...path]/route.ts"
import { auth } from '@/lib/auth/server';

export const { GET, POST } = auth.handler();
```

## เพิ่ม middleware สำหรับการยืนยันตัวตน

middleware จะทำให้แน่ใจว่าผู้ใช้ผ่านการยืนยันตัวตนแล้วก่อนเข้าถึง routes ที่ได้รับการป้องกัน สร้างไฟล์ `proxy.ts` ที่รูทของโปรเจ็กต์:

**หมายเหตุ: ความเข้ากันได้ของเวอร์ชัน Next.js**

`proxy.ts` ใช้แทน `middleware.ts` ใน Next.js 16 สำหรับเวอร์ชันก่อนหน้า ให้ตั้งชื่อไฟล์ว่า `middleware.ts` และ export `default function middleware` แทน `proxy` โดยโลจิกการยืนยันตัวตนเหมือนกัน

```typescript filename="proxy.ts"
import { auth } from '@/lib/auth/server';

export default auth.middleware({
  // Redirects unauthenticated users to sign-in page
  loginUrl: '/auth/sign-in',
});

export const config = {
  matcher: [
    // Protected routes requiring authentication
    '/account/:path*',
  ],
};
```

**หมายเหตุ:** ตอนนี้โปรเจ็กต์ Next.js ของคุณได้รับการตั้งค่าให้ใช้ Managed Better Auth อย่างสมบูรณ์แล้ว ต่อไปให้ตั้งค่า auth clients

## ตั้งค่า auth client

สร้าง auth client ใน `lib/auth/client.ts` สำหรับการทำงานด้านการยืนยันตัวตนฝั่ง client (การส่งฟอร์ม, hooks และอื่นๆ)

**หมายเหตุ:** server-side `auth` instance ถูกสร้างไว้ในขั้นตอนก่อนหน้าแล้ว ส่วน client แยกออกมาต่างหากและจัดการการทำงานด้านการยืนยันตัวตนในเบราว์เซอร์

```tsx filename="lib/auth/client.ts"
'use client';

import { createAuthClient } from '@neondatabase/auth/next';

export const authClient = createAuthClient();
```

## สร้างฟอร์มสมัครสมาชิก

สร้างฟอร์มสมัครสมาชิกและ action ในไฟล์ `app/auth/sign-up/page.tsx` และ `app/auth/sign-up/actions.ts` ตามลำดับ โดยใช้ auth instance ที่เราสร้างไว้ในขั้นตอนก่อนหน้า

- ในการสร้างผู้ใช้ด้วยอีเมลและรหัสผ่าน เราจะใช้ `auth.signUp.email()` พร้อมชื่อผู้ใช้, อีเมล และรหัสผ่าน
- คุณสามารถเพิ่ม business logic ก่อนเรียก API ได้ เช่น จำกัดการสมัครสมาชิกเฉพาะอีเมลที่ลงท้ายด้วย `@my-company.com`

**Signup action**

คัดลอกและวางโค้ดต่อไปนี้ลงในไฟล์ `app/auth/sign-up/actions.ts`:

```ts
'use server';

import { auth } from '@/lib/auth/server';
import { redirect } from 'next/navigation';

export async function signUpWithEmail(
  _prevState: { error: string } | null,
  formData: FormData
) {
  const email = formData.get('email') as string;

  if (!email) {
    return { error: "Email address must be provided." }
  }

  // Optionally restrict sign ups based on email address
  // if (!email.trim().endsWith("@my-company.com")) {
  //  return { error: 'Email must be from my-company.com' };
  // }

  const { error } = await auth.signUp.email({
    email,
    name: formData.get('name') as string,
    password: formData.get('password') as string,
  });

  if (error) {
    return { error: error.message || 'Failed to create account' };
  }

  redirect('/');
}
```

## สร้างหน้าแรก

ในขั้นตอนสุดท้าย ให้สร้างหน้าแรกและแสดงสถานะผู้ใช้ที่ผ่านการยืนยันตัวตนแล้ว:

```typescript filename="app/page.tsx"
import { auth } from '@/lib/auth/server';
import Link from 'next/link';

// Server components using auth methods must be rendered dynamically
export const dynamic = 'force-dynamic';

export default async function Home() {
  const { data: session } = await auth.getSession();

  if (session?.user) {
    return (
      <div className="flex flex-col gap-2 min-h-screen items-center justify-center bg-gray-900">
        <h1 className="mb-4 text-4xl">
          Logged in as <span className="font-bold underline">{session.user.name}</span>
        </h1>
      </div>
    );
  }

  return (
    <div className="flex flex-col gap-2 min-h-screen items-center justify-center bg-gray-900">
      <h1 className="mb-4 text-4xl font-bold">Not logged in</h1>
      <div className="flex item-center gap-2">
        <Link
          href="/auth/sign-up"
          className="inline-flex text-lg text-indigo-400 hover:underline"
        >
          Sign-up
        </Link>
        <Link
          href="/auth/sign-in"
          className="inline-flex text-lg text-indigo-400 hover:underline"
        >
          Sign-in
        </Link>
      </div>
    </div>
  );
}
```

## เมธอด SDK ที่พร้อมใช้งาน

ทั้ง `authClient` และ `auth` มีเมธอด API ที่คล้ายกัน ใช้ `authClient` สำหรับ client components และใช้ `auth` สำหรับ server components, server actions และ API routes

- [authClient.signUp.email()](https://neon.com/docs/reference/javascript-sdk#auth-signup) / `auth.signUp.email()` - สร้างบัญชีผู้ใช้ใหม่
- [authClient.signIn.email()](https://neon.com/docs/reference/javascript-sdk#auth-signinwithpassword) / `auth.signIn.email()` - เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน
- [authClient.signOut()](https://neon.com/docs/reference/javascript-sdk#auth-signout) / `auth.signOut()` - ออกจากระบบผู้ใช้ปัจจุบัน
- [authClient.getSession()](https://neon.com/docs/reference/javascript-sdk#auth-getsession) / `auth.getSession()` - รับเซสชันปัจจุบัน
- `authClient.updateUser()` / `auth.updateUser()` - อัปเดตรายละเอียดผู้ใช้

`auth` instance ยังมี `.handler()` สำหรับ API routes และ `.middleware()` สำหรับป้องกัน routes ด้วย
