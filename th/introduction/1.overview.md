# Managed Better Auth

ระบบยืนยันตัวตนที่จัดการให้และแตกบรานช์ไปพร้อมกับฐานข้อมูลของคุณ

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

Managed Better Auth คือบริการจัดการการยืนยันตัวตนในแบ็กเอนด์ของ Neon สำหรับแอปและเอเจนต์ โดยจัดเก็บผู้ใช้ เซสชัน และการตั้งค่าการยืนยันตัวตนไว้ในฐานข้อมูล Neon ของคุณโดยตรง เมื่อคุณสร้างบรานช์ของฐานข้อมูล สถานะการยืนยันตัวตนทั้งหมดจะแตกบรานช์ตามไปด้วย ทำให้คุณสามารถทดสอบเวิร์กโฟลว์การยืนยันตัวตนจริงในสภาพแวดล้อมพรีวิวได้

## คู่มือเริ่มต้นอย่างรวดเร็ว

เลือกเฟรมเวิร์กของคุณเพื่อเริ่มต้น:

- [Next.js](https://neon.com/docs/auth/quick-start/nextjs-api-only): เริ่มต้นอย่างรวดเร็วด้วยเมธอด API
- [React](https://neon.com/docs/auth/quick-start/react): เริ่มต้นอย่างรวดเร็วด้วยเมธอด API
- [TanStack Router](https://neon.com/docs/auth/quick-start/tanstack-router): ใช้งานร่วมกับคอมโพเนนต์ UI

## ตั้งค่าด้วยเอดิเตอร์ AI ของคุณ

วิธีที่เร็วที่สุดในการเชื่อมต่อเอดิเตอร์ของคุณกับ Managed Better Auth คือรัน `npx neon@latest init` จากรูทของโปรเจ็กต์:

```bash
npx neon@latest init
```

คำสั่งนี้จะตั้งค่า [Neon MCP server](https://neon.com/docs/ai/neon-mcp-server) และติดตั้ง **[Agent Skills](https://neon.com/docs/ai/agent-skills)** (`neon-postgres`) ลงในโปรเจ็กต์ของคุณ ทั้งสองส่วนจะช่วยให้คุณตั้งค่า Managed Better Auth ได้สองวิธี:

1. **ตั้งค่า Managed Better Auth บนบรานช์ของคุณ (MCP)** หลังจากรัน `init` แล้ว ให้ขอให้ผู้ช่วยของคุณเปิดใช้งานและตั้งค่าการยืนยันตัวตนด้วยภาษาธรรมชาติ MCP server มีเครื่องมือต่อไปนี้:

   - `provision_neon_auth`: เปิดใช้งาน Managed Better Auth บนบรานช์
   - `configure_neon_auth`: ตั้งค่า OAuth provider, อีเมล, วิธีการลงชื่อเข้าใช้, trusted domain และอื่นๆ
   - `get_neon_auth_config`: อ่านการตั้งค่าปัจจุบัน

   ดูรายละเอียดได้ที่ [Neon MCP Server: เครื่องมือ Managed Better Auth](https://neon.com/docs/ai/neon-mcp-server#supported-actions-tools)

2. **เพิ่ม Managed Better Auth ลงในแอปพลิเคชันของคุณ (Agent Skills)** Skills จะสอนผู้ช่วยของคุณเกี่ยวกับวิธีติดตั้ง SDK, ตัวแปรสภาพแวดล้อม และ route สำหรับเฟรมเวิร์กของคุณ ใช้คู่มือเริ่มต้นอย่างรวดเร็วในหน้านี้ หรือถามผู้ช่วยของคุณโดยตรง

**ตัวอย่างพรอมต์:**

```text
Set up Managed Better Auth for my project. Enable Google OAuth and email/password sign-in,
and set the application name to "My App".
```

คุณยังสามารถเปิดใช้งาน Managed Better Auth ใน [Neon Console](https://console.neon.tech) (Project → Branch → Auth) และตั้งค่าต่างๆ ด้วยตนเองได้

## ทำไมจึงควรใช้ Managed Better Auth?

- **ข้อมูล identity อยู่ในฐานข้อมูลของคุณ**  
  ข้อมูลการยืนยันตัวตนทั้งหมดถูกจัดเก็บไว้ในสคีมา `neon_auth` คุณสามารถสืบค้นข้อมูลด้วย SQL และใช้งานร่วมกับนโยบาย Row Level Security (RLS) ได้

- **ไม่ต้องจัดการเซิร์ฟเวอร์**  
  Managed Better Auth ทำงานในรูปแบบบริการ REST API ที่มีการจัดการให้ คุณสามารถตั้งค่าผ่าน Console และใช้ [client SDK](https://neon.com/docs/reference/javascript-sdk) หรือ [server SDK](https://neon.com/docs/auth/reference/nextjs-server) ภายในแอป โดยไม่ต้องดูแลโครงสร้างพื้นฐานเอง

- **การยืนยันตัวตนที่แตกบรานช์ไปพร้อมกับข้อมูลของคุณ**  
  ทดสอบขั้นตอนการสมัครสมาชิก การเข้าสู่ระบบ การรีเซ็ตรหัสผ่าน และ OAuth ภายในบรานช์ที่แยกออกจากกันได้โดยไม่กระทบข้อมูล production

## สร้างบน Better Auth

Managed Better Auth ขับเคลื่อนด้วย [Better Auth](https://www.better-auth.com/) ซึ่งหมายความว่าคุณจะได้ใช้ API ที่คุ้นเคย คุณสามารถใช้คอมโพเนนต์ UI ของ Better Auth หรือเรียกใช้เมธอดการยืนยันตัวตนโดยตรงเพื่อสร้าง UI ของคุณเอง

ปัจจุบัน Managed Better Auth รองรับ Better Auth เวอร์ชัน **1.4.18**

### เมื่อใดควรใช้ Managed Better Auth เทียบกับการโฮสต์ Better Auth เอง

Managed Better Auth คือบริการจัดการการยืนยันตัวตนที่ติดตั้งมาใน Lakebase Postgres บน Neon:

- **การยืนยันตัวตนที่รับรู้บรานช์**: ทุกบรานช์ของ Neon จะมีสภาพแวดล้อมการยืนยันตัวตนที่แยกออกจากกันเป็นของตัวเอง คุณจึงสามารถทดสอบฟีเจอร์การยืนยันตัวตนได้โดยไม่ส่งผลกระทบต่อบรานช์ production
- **การผสานรวม Data API ในตัว**: การตรวจสอบ JWT token สำหรับ Data API รองรับ Managed Better Auth โดยตรง
- **ไม่มีโครงสร้างพื้นฐานที่ต้องจัดการ**: Managed Better Auth ถูก deploy ใน region เดียวกับฐานข้อมูลของคุณ ช่วยลด latency โดยที่คุณไม่จำเป็นต้องรันโครงสร้างพื้นฐานสำหรับการยืนยันตัวตนเอง
- **OAuth credential ที่ใช้ร่วมกันสำหรับการทดสอบ**: เริ่มต้นได้อย่างรวดเร็วด้วย Google OAuth credential ที่พร้อมใช้งานทันที ช่วยลดความซับซ้อนของการตั้งค่าสำหรับการทดสอบและการสร้างต้นแบบ

การโฮสต์ Better Auth เองเหมาะสมหากคุณต้องการ:

- ความยืดหยุ่นในการตั้งค่าการยืนยันตัวตน เช่น plugin, hook และ option แบบกำหนดเองที่ Managed Better Auth ยังไม่รองรับ
- ควบคุมโค้ดการยืนยันตัวตนได้ทั้งหมด และสามารถรันโค้ดดังกล่าวภายในโครงสร้างพื้นฐานของคุณเอง

สำหรับรายละเอียดเพิ่มเติมเกี่ยวกับความแตกต่างของ SDK ระหว่าง `@neondatabase/auth` และ `better-auth/client` โปรดดู [เหตุผลที่ควรใช้ @neondatabase/auth แทน better-auth/client](https://github.com/neondatabase/neon-js/blob/main/packages/auth/neon-auth_vs_better-auth.md)

เมื่อ Managed Better Auth พัฒนาต่อไป จะมีการเพิ่มการเชื่อมต่อและฟีเจอร์ของ Better Auth มากขึ้น ตรวจสอบ [roadmap](https://neon.com/docs/auth/roadmap) เพื่อดูว่าปัจจุบันรองรับอะไรบ้างและมีอะไรที่จะเพิ่มเข้ามาในอนาคต

## การใช้งานพื้นฐาน

เปิดใช้งาน Auth ใน Neon Console หรือ [ผ่านเอดิเตอร์ AI ของคุณ](https://neon.com/docs/auth/overview#set-up-with-your-ai-editor) จากนั้นเพิ่มการยืนยันตัวตนลงในแอป

**สำหรับ Next.js (server-side):**

ดูเอกสาร API ฉบับสมบูรณ์ได้ที่ [เอกสารอ้างอิง Next.js Server SDK](https://neon.com/docs/auth/reference/nextjs-server)

```typescript filename="lib/auth/server.ts"
import { createNeonAuth } from '@neondatabase/auth/next/server';

export const auth = createNeonAuth({
  baseUrl: process.env.NEON_AUTH_BASE_URL!,
  cookies: { secret: process.env.NEON_AUTH_COOKIE_SECRET! },
});
```

```typescript filename="app/api/auth/[...path]/route.ts"
import { auth } from '@/lib/auth/server';

export const { GET, POST } = auth.handler();
```

**สำหรับ React/Vite (client-side):**

ดูเอกสาร API ฉบับสมบูรณ์ได้ที่ [เอกสารอ้างอิง Client SDK](https://neon.com/docs/reference/javascript-sdk) หากคุณต้องการใช้ client เพียงตัวเดียวสำหรับทั้ง Neon Auth และ Data API ให้ initialize `createClient()` จาก Neon URL เดียว ตามที่แสดงใน [การ initialize `createClient()`](https://neon.com/docs/reference/javascript-sdk#initializing)

```typescript filename="src/auth.ts"
import { createAuthClient } from '@neondatabase/neon-js/auth';

export const authClient = createAuthClient(import.meta.env.VITE_NEON_AUTH_URL);
```

```tsx filename="src/App.tsx"
import { NeonAuthUIProvider, AuthView } from '@neondatabase/auth-ui';
import { authClient } from './auth';

export default function App() {
  return (
    <NeonAuthUIProvider authClient={authClient}>
      <AuthView pathname="sign-in" />
    </NeonAuthUIProvider>
  );
}
```

## กรณีการใช้งาน

- **การยืนยันตัวตนสำหรับ production**  
  ใช้ Managed Better Auth เป็นระบบ identity สำหรับแอปของคุณ จัดเก็บผู้ใช้ เซสชัน และการตั้งค่า OAuth ไว้ใน Postgres โดยตรง และใช้งานร่วมกับ RLS เพื่อควบคุมการเข้าถึงที่ปลอดภัยโดยมีฐานข้อมูลเป็นศูนย์กลาง

- **สภาพแวดล้อมพรีวิว**  
  ทดสอบขั้นตอนการยืนยันตัวตนแบบครบถ้วนใน Vercel preview ด้วยผู้ใช้และเซสชันจริง

- **SaaS แบบ multi-tenant**  
  ทดสอบลำดับชั้นของ organization และ role ที่ซับซ้อนได้อย่างปลอดภัยภายในบรานช์ที่แยกออกจากกัน

- **เวิร์กโฟลว์ CI/CD**  
  รันการทดสอบการยืนยันตัวตนแบบ end-to-end โดยไม่กระทบ production [Neon Create Branch GitHub Action](https://github.com/marketplace/actions/neon-create-branch-github-action) รองรับการดึง URL การยืนยันตัวตนเฉพาะของแต่ละบรานช์ เพื่อใช้ทดสอบขั้นตอนการยืนยันตัวตนในเวิร์กโฟลว์ของ GitHub Actions

- **เวิร์กโฟลว์การพัฒนา**  
  สร้างสภาพแวดล้อมที่สมบูรณ์ได้ทันทีพร้อมทั้งฐานข้อมูลและระบบยืนยันตัวตน

ดูรายละเอียดเกี่ยวกับวิธีที่การยืนยันตัวตนแตกบรานช์ไปพร้อมกับฐานข้อมูลของคุณได้ที่ [การแตกบรานช์ของการยืนยันตัวตน](https://neon.com/docs/auth/branching-authentication)

## ความพร้อมใช้งาน

ปัจจุบัน Managed Better Auth พร้อมใช้งานเฉพาะ AWS region เท่านั้น และยังไม่รองรับ Azure

ปัจจุบัน Managed Better Auth ไม่รองรับโปรเจ็กต์ที่เปิดใช้งาน [IP Allow](https://neon.com/docs/manage/projects#configure-ip-allow) หรือ [Private Networking](https://neon.com/docs/guides/neon-private-networking)

## ราคา

Managed Better Auth รวมอยู่ใน Neon ทุกแพ็กเกจ โดยคิดตามจำนวน Monthly Active Users (MAU):

- **Free**: สูงสุด 60,000 MAU
- **Launch**: สูงสุด 1M MAU
- **Scale**: สูงสุด 1M MAU

MAU (Monthly Active User) คือผู้ใช้หนึ่งรายที่ยืนยันตัวตนอย่างน้อยหนึ่งครั้งภายในรอบการเรียกเก็บเงินรายเดือน หากคุณต้องการมากกว่า 1M MAU ให้ขอเพิ่มขีดจำกัดผ่าน [แบบฟอร์มความคิดเห็นใน Console](https://console.neon.tech/app/settings?modal=feedback\&modalparams=%22Neon%20auth%20limit%20increase%22)

ดูรายละเอียดเพิ่มเติมได้ที่ [แพ็กเกจ Neon](https://neon.com/docs/introduction/plans#auth)

## การย้ายจาก Stack Auth

หากคุณกำลังใช้ Neon Auth เวอร์ชันก่อนหน้าผ่าน Stack Auth เวอร์ชันดังกล่าวจะยังคงใช้งานได้ต่อไป เมื่อคุณพร้อมย้ายไปใช้ implementation ใหม่ที่ใช้ Better Auth โปรดดู [คู่มือการย้าย](https://neon.com/docs/auth/migrate/from-legacy-auth)
