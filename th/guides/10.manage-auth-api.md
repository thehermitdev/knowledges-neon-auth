> สรุป: การดำเนินการผ่าน REST API ของ Managed Better Auth สำหรับเปิดใช้งาน (POST), ดึงข้อมูล (GET), อัปเดต (PATCH) และปิดใช้งาน (DELETE) auth แยกตามแต่ละบรานช์ พร้อมตัวอย่าง curl และเอกสารอ้างอิงฟิลด์ response แบบครบถ้วน ใช้หน้านี้เมื่อต้องการทำ auth provisioning หรือ teardown แบบอัตโนมัติ: response ตอนเปิดใช้งานเป็นการเรียกเพียงครั้งเดียวที่คืน `pub_client_key` และ `secret_server_key` และแฟล็ก `delete_data` ใน DELETE จะควบคุมว่าจะลบสคีมา `neon_auth` อย่างถาวรหรือไม่ นอกจากนี้ยังครอบคลุม endpoint ระดับบรานช์ที่เกี่ยวข้องสำหรับ OAuth providers, การตั้งค่าอีเมล, domains, users, plugins และเว็บฮุก รวมถึง MCP tools ที่เทียบเท่ากันสำหรับเวิร์กโฟลว์ใน AI editor

# จัดการ Managed Better Auth ผ่าน API

เปิดใช้งาน ตั้งค่า และปิดใช้งาน Managed Better Auth ด้วย Neon API

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

คุณสามารถจัดการ Managed Better Auth ด้วยโค้ดผ่าน [Neon API](https://neon.com/docs/reference/api) นอกจากนี้ยังสามารถเปิดใช้งานและตั้งค่า Managed Better Auth จาก AI editor ผ่าน [Neon MCP server](https://neon.com/docs/ai/neon-mcp-server#supported-actions-tools) (`provision_neon_auth`, `configure_neon_auth`, `get_neon_auth_config`) ดู [ตั้งค่าด้วย AI editor ของคุณ](https://neon.com/docs/auth/overview#set-up-with-your-ai-editor)

**หมายเหตุ:** Managed Better Auth ทำงานที่ **ระดับบรานช์** แต่ละบรานช์สามารถมีการตั้งค่า auth แยกจากกันได้อย่างอิสระ ซึ่งหมายความว่าบรานช์ preview และ development สามารถมี state ของ auth ที่แยกจากบรานช์ production ของคุณได้

## ข้อกำหนดเบื้องต้น

- [Neon API key](https://neon.com/docs/manage/api-keys)
- โปรเจ็กต์ Neon ที่มีอย่างน้อยหนึ่งบรานช์

ทุก request ใช้ base URL `https://console.neon.tech/api/v2` และต้องมี header `Authorization: Bearer $NEON_API_KEY` ค่า `project_id` และ `branch_id` จะถูกคืนเมื่อคุณ [สร้างโปรเจ็กต์](https://neon.com/docs/manage/projects#create-a-project-with-the-api) หรือ [แสดงรายการบรานช์](https://neon.com/docs/manage/branches#list-branches-with-the-api) ผ่าน API

## เปิดใช้งาน Managed Better Auth

ส่ง request แบบ `POST` เพื่อเปิดใช้งาน Managed Better Auth บนบรานช์:

```bash
curl -X POST 'https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth' \
  -H 'Authorization: Bearer $NEON_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"auth_provider": "better_auth"}'
```

Response (201 Created):

```json
{
  "auth_provider": "better_auth",
  "auth_provider_project_id": "cab6949a-10e3-4d25-a879-512beed281e3",
  "pub_client_key": "",
  "secret_server_key": "",
  "jwks_url": "https://ep-example.neonauth.us-east-1.aws.neon.tech/neondb/auth/.well-known/jwks.json",
  "schema_name": "neon_auth",
  "table_name": "users_sync",
  "base_url": "https://ep-example.neonauth.us-east-1.aws.neon.tech/neondb/auth"
}
```

Response ประกอบด้วย:

| Field                      | Description                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------- |
| `auth_provider`            | provider ที่ตั้งค่าไว้ (`better_auth`)                                                                    |
| `auth_provider_project_id` | ID เฉพาะของ instance ของ auth provider                                                                   |
| `pub_client_key`           | public client key (แสดงครั้งเดียวตอนสร้าง และอาจเป็นค่าว่างสำหรับ `better_auth`)                         |
| `secret_server_key`        | secret server key (แสดงครั้งเดียวตอนสร้าง และอาจเป็นค่าว่างสำหรับ `better_auth`)                         |
| `jwks_url`                 | JWKS endpoint สำหรับการตรวจสอบ JWT                                                                        |
| `schema_name`              | สคีมาฐานข้อมูลที่สร้างสำหรับตาราง auth (`neon_auth`)                                                     |
| `table_name`               | ชื่อตารางสำหรับข้อมูลผู้ใช้ที่ซิงก์ (`users_sync`)                                                       |
| `base_url`                 | Base URL ของบริการ auth ซึ่งใช้สำหรับการตั้งค่า SDK และ interactive API reference (`/reference`)         |

**สำคัญ:** response ตอนเปิดใช้งานเป็นครั้งเดียวที่ API จะคืน `pub_client_key` และ `secret_server_key` ให้จัดเก็บค่าเหล่านี้อย่างปลอดภัย request แบบ `GET` หลังจากนั้นจะไม่มีฟิลด์เหล่านี้ สำหรับตัวอย่างการเริ่มต้น client ที่รวม Neon Auth และ Data API จาก Neon URL เดียว โปรดดู [`createClient()` ในเอกสารอ้างอิง JavaScript SDK](https://neon.com/docs/reference/javascript-sdk#initializing)

หากเปิดใช้งาน Managed Better Auth บนบรานช์อยู่แล้ว การเรียกนี้จะคืน error

**เคล็ดลับ: การใช้ฐานข้อมูลที่ไม่ใช่ค่าเริ่มต้น**

โดยค่าเริ่มต้น Managed Better Auth จะใช้ฐานข้อมูลเริ่มต้นของบรานช์ หากต้องการใช้ฐานข้อมูลอื่น ให้เพิ่ม `database_name` ลงใน request body: `{"auth_provider": "better_auth", "database_name": "my_other_db"}`

## ดูการตั้งค่า Auth

ดึงการตั้งค่า Managed Better Auth ปัจจุบันสำหรับบรานช์:

```bash
curl -X GET 'https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth' \
  -H 'Authorization: Bearer $NEON_API_KEY'
```

Response (200 OK):

```json
{
  "auth_provider": "better_auth",
  "auth_provider_project_id": "cab6949a-10e3-4d25-a879-512beed281e3",
  "branch_id": "br-example-abc123",
  "db_name": "neondb",
  "created_at": "2026-02-26T04:29:05Z",
  "owned_by": "neon",
  "jwks_url": "https://ep-example.neonauth.us-east-1.aws.neon.tech/neondb/auth/.well-known/jwks.json",
  "base_url": "https://ep-example.neonauth.us-east-1.aws.neon.tech/neondb/auth",
  "name": "My App"
}
```

## อัปเดตการตั้งค่า auth

อัปเดตการตั้งค่า auth สำหรับบรานช์ ปัจจุบันรองรับการเปลี่ยนชื่อแอปพลิเคชันที่แสดงในข้อความ auth สำหรับผู้ใช้ ใช้ได้เฉพาะ integration ของ Managed Better Auth โดยค่าเริ่มต้นจะใช้ชื่อโปรเจ็กต์ Neon

```bash
curl -X PATCH 'https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth/config' \
  -H 'Authorization: Bearer $NEON_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"name": "My App"}'
```

Response (200 OK):

```json
{
  "name": "My App"
}
```

| Field  | Description                                                   |
| ------ | ------------------------------------------------------------- |
| `name` | ชื่อที่แสดงในข้อความ auth สำหรับผู้ใช้ (1-256 ตัวอักษร)      |

แต่ละบรานช์จัดการ application name ของตัวเองแยกจากกัน คุณยังสามารถอัปเดตค่านี้จากหน้า **Auth** > แท็บ **Configuration** > แผง **Project Info** ใน Neon Console ได้

## ปิดใช้งาน Managed Better Auth

ส่ง request แบบ `DELETE` เพื่อปิดใช้งาน Managed Better Auth บนบรานช์:

```bash
curl -X DELETE 'https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth' \
  -H 'Authorization: Bearer $NEON_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"delete_data": true}'
```

Response (200 OK): body ว่างเปล่า

ฟิลด์ `delete_data` ควบคุมว่าระบบจะลบสคีมา `neon_auth` ออกจากฐานข้อมูลหรือไม่:

- **`true`**: ลบสคีมา `neon_auth` และตาราง auth ทั้งหมด (users, sessions, accounts)
- **`false`** (ค่าเริ่มต้น): ปิดใช้งานบริการ auth แต่คงสคีมาและข้อมูลไว้ คุณสามารถเปิดใช้งานอีกครั้งภายหลังได้โดยไม่สูญเสียข้อมูลผู้ใช้

**คำเตือน:** การตั้งค่า `delete_data` เป็น `true` จะลบข้อมูล auth ทั้งหมดออกจากฐานข้อมูลอย่างถาวร คุณไม่สามารถย้อนกลับการดำเนินการนี้ได้

## Endpoint ที่เกี่ยวข้องกับ auth

Neon API ยังมี endpoint สำหรับจัดการการตั้งค่า auth ที่ระดับบรานช์ โดย endpoint เหล่านี้อยู่ที่ `https://console.neon.tech/api/v2/projects/{project_id}/branches/{branch_id}/auth/...`:

| Endpoint                | Methods                  | Description                                                                                 |
| ----------------------- | ------------------------ | ------------------------------------------------------------------------------------------- |
| `/domains`              | GET, POST, DELETE        | จัดการ trusted redirect domains                                                             |
| `/oauth_providers`      | GET, POST, PATCH, DELETE | ตั้งค่า OAuth providers (Google, GitHub เป็นต้น)                                            |
| `/email_provider`       | GET, PATCH               | ตั้งค่าผู้ให้บริการอีเมล                                                                   |
| `/email_and_password`   | GET, PATCH               | ตั้งค่าการยืนยันตัวตนด้วยอีเมล/รหัสผ่าน                                                    |
| `/users`                | POST, DELETE, PUT        | สร้าง ลบ และจัดการ role ของผู้ใช้                                                          |
| `/plugins`              | GET, PATCH               | ดูและตั้งค่า [auth plugins](https://neon.com/docs/auth/guides/plugins)                      |
| `/plugins/magic-link`   | PATCH                    | ตั้งค่า [Magic Link plugin](https://neon.com/docs/auth/guides/plugins/magic-link)           |
| `/plugins/phone-number` | GET, PATCH               | ตั้งค่า [Phone Number plugin](https://neon.com/docs/auth/guides/plugins/phone-number)       |
| `/webhooks`             | GET, PUT                 | ตั้งค่าการแจ้งเตือนเว็บฮุก                                                                  |
| `/allow_localhost`      | GET, PATCH               | เปิดหรือปิดการเข้าถึง localhost สำหรับ development                                         |
| `/config`               | PATCH                    | อัปเดตการตั้งค่า auth (application name)                                                    |
| `/send_test_email`      | POST                     | ส่งอีเมลทดสอบเพื่อตรวจสอบการตั้งค่าอีเมล                                                   |

สำหรับรายละเอียด request/response แบบครบถ้วนของ endpoint เหล่านี้ โปรดดู [Interactive API Reference](https://neon.com/docs/reference/api)

**เคล็ดลับ: TypeScript SDK**

คุณยังสามารถจัดการ Managed Better Auth ด้วย [Neon TypeScript SDK](https://neon.com/docs/reference/typescript-sdk)
