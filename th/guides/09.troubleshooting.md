> สรุป: แนวทางแก้ไขปัญหาสำหรับข้อผิดพลาดทั่วไปของ Managed Better Auth ใน `@neondatabase/auth` (Next.js) และ `@neondatabase/neon-js` (React SPA) ครอบคลุมกรณีไม่มี `NEON_AUTH_COOKIE_SECRET`, ไม่มี `force-dynamic` ใน server components, ข้อผิดพลาด upstream แบบ `NETWORK_DNS` / `NETWORK_TIMEOUT` และ OAuth `redirect_uri_mismatch` จากการตั้งค่า callback URI ไม่ถูกต้อง ใช้หน้านี้เมื่อ Managed Better Auth ทำงานล้มเหลวตอนเริ่มต้น, เซสชันไม่คงอยู่ หรือการเข้าสู่ระบบด้วย OAuth วนกลับไปยัง provider แทนที่จะกลับมายังแอป

# การแก้ไขปัญหา Auth

ปัญหาที่พบบ่อยเมื่อใช้งาน Managed Better Auth และวิธีแก้ไข

หน้านี้ครอบคลุมปัญหาที่พบบ่อยเมื่อ integrate [Managed Better Auth](https://neon.com/docs/auth/overview) เข้ากับ `@neondatabase/auth` (Next.js) หรือ `@neondatabase/neon-js` (React SPAs)

## ไม่มี NEON_AUTH_COOKIE_SECRET

หากแอป Next.js แสดง error เกี่ยวกับ cookie secret ที่ไม่มีหรือไม่ถูกต้องตอนเริ่มต้น แสดงว่า environment variable `NEON_AUTH_COOKIE_SECRET` ยังไม่ได้กำหนดหรือสั้นเกินไป secret ต้องมีอย่างน้อย 32 ตัวอักษรสำหรับ HMAC-SHA256 สร้างค่าได้ด้วย:

```bash
openssl rand -base64 32
```

ดูรายการ environment variables ที่จำเป็นทั้งหมดได้ที่ [Next.js Server SDK reference](https://neon.com/docs/auth/reference/nextjs-server)

## ไม่มี force-dynamic ใน server components

หาก `next build` ล้มเหลวด้วย error "Dynamic server usage" บนหน้าที่เรียก `auth.getSession()` แสดงว่า server component ต้อง opt out จาก static rendering:

```typescript
export const dynamic = 'force-dynamic';

export default async function Page() {
  const { data: session } = await auth.getSession();
  // ...
}
```

จำเป็นต้องทำเช่นนี้เพราะ `getSession()` อ่าน cookies ซึ่งพร้อมใช้งานเฉพาะตอนที่มี request เท่านั้น ดู [getSession](https://neon.com/docs/auth/reference/nextjs-server#get-session) ใน Next.js Server SDK reference

## Logging ของ Managed Better Auth server ใน terminal

คุณอาจเห็นบรรทัดแบบมีโครงสร้างระดับ **`warn`** หรือ **`error`** ใน console ของ Next.js server เมื่อ auth proxy ติดต่อ Managed Better Auth ไม่ได้ หรือเมื่อการตรวจสอบ session cookies ล้มเหลว พฤติกรรมนี้เป็นไปตามที่คาดไว้: SDK กำหนดค่าเริ่มต้นเป็น **`logLevel: 'warn'`** และสามารถ opt out ได้

หากต้องการปิด output ของ Managed Better Auth ใน console:

```typescript
export const auth = createNeonAuth({
  baseUrl: process.env.NEON_AUTH_BASE_URL!,
  cookies: { secret: process.env.NEON_AUTH_COOKIE_SECRET! },
  logLevel: 'silent',
});
```

หากต้องการตรวจสอบเพิ่มเติม ให้ใช้ **`logLevel: 'debug'`** หรือ **`logger`** แบบกำหนดเอง ดู [Server logging](https://neon.com/docs/auth/reference/nextjs-server#server-logging)

## ข้อผิดพลาด upstream NETWORK_*

Server actions หรือ API routes อาจส่งคืน error ที่มีค่า **`code`** เช่น **`NETWORK_DNS`**, **`NETWORK_REFUSED`** หรือ **`NETWORK_TIMEOUT`** ซึ่งหมายความว่าแอปของคุณติดต่อ Auth server ที่ **`NEON_AUTH_BASE_URL`** ไม่ได้ (เช่น พิมพ์ผิด, ใช้ URL ของบรานช์ไม่ถูกต้อง, เครือข่ายออฟไลน์ หรือมีปัญหา TLS)

1. ตรวจสอบว่า **`NEON_AUTH_BASE_URL`** ใน `.env.local` ตรงกับ Auth URL ใน Neon Console (Project → Branch → Auth → Configuration)
2. รีสตาร์ต dev server หลังเปลี่ยน env vars
3. เปิดใช้ **`logLevel: 'debug'`** แล้วลองอีกครั้ง โดย logs จะมีฟิลด์ **`detail`** ที่ปลอดภัย

ดูรายการ code ทั้งหมดได้ที่ [Upstream fetch errors](https://neon.com/docs/auth/reference/nextjs-server#upstream-fetch-errors)

## Cookies ถูกบล็อกใน iframe หรือ cross-site embeds

Cookies ของ Managed Better Auth ใช้ค่าเริ่มต้นเป็น **`SameSite=Strict`** หากแอปของคุณทำงานอยู่ภายใน **iframe** ของเว็บไซต์อื่น หรือต้องใช้ cookies ระหว่างการนำทางข้ามไซต์ระดับบนสุด เซสชันอาจไม่คงอยู่

กำหนด SameSite mode ให้ชัดเจนตอนสร้าง auth instance:

```typescript
export const auth = createNeonAuth({
  baseUrl: process.env.NEON_AUTH_BASE_URL!,
  cookies: {
    secret: process.env.NEON_AUTH_COOKIE_SECRET!,
    sameSite: 'lax', // or 'none' for third-party iframe contexts (requires HTTPS)
  },
});
```

ดู [Configuration reference](https://neon.com/docs/auth/reference/nextjs-server#configuration-reference) และ [Next.js quick start](https://neon.com/docs/auth/quick-start/nextjs-api-only)

## การใช้รูปแบบ API ของ v0.1

หากคุณกำลังอัปเกรดจาก v0.1 ให้ใช้ `createNeonAuth()` + `auth.handler()` แทน `authApiHandler()` แบบ standalone เดิม ดูรายละเอียดได้ที่ [migration guide](https://neon.com/docs/auth/migrate/from-auth-v0.1)

## การใช้ useSession() โดยไม่มี adapter ใน React SPA

ใน React SPA การใช้ `createAuthClient(url)` โดยไม่มี adapter จะคืน vanilla client ที่ไม่มี React hooks การเรียก `useSession()` บน client นี้จะล้มเหลว ให้ส่ง `BetterAuthReactAdapter()` เข้าไป หรือใช้คอมโพเนนต์ UI (`SignedIn`, `SignedOut`, `UserButton`) ซึ่งไม่ต้องใช้ adapter

```typescript
import { createAuthClient } from '@neondatabase/neon-js/auth';
import { BetterAuthReactAdapter } from '@neondatabase/neon-js/auth/react/adapters';

const authClient = createAuthClient(url, {
  adapter: BetterAuthReactAdapter(),
});
```

[TanStack Router quick start](https://neon.com/docs/auth/quick-start/tanstack-router) แสดงตัวอย่างการตั้งค่าแบบสมบูรณ์พร้อม React adapter

## Import BetterAuthReactAdapter ผิด

ต้อง import adapter จาก subpath และเรียกใช้งานเป็นฟังก์ชัน:

```typescript
// Wrong
import { BetterAuthReactAdapter } from '@neondatabase/neon-js';

// Correct
import { BetterAuthReactAdapter } from '@neondatabase/neon-js/auth/react/adapters';
const client = createAuthClient(url, { adapter: BetterAuthReactAdapter() });
```

## CSS import ขัดแย้งกัน

เลือกใช้วิธี import CSS เพียงวิธีเดียว ห้ามใช้ทั้งสองวิธีพร้อมกัน เพราะจะทำให้ styles ซ้ำกัน:

- **ไม่ใช้ Tailwind:** `import '@neondatabase/auth-ui/css'`
- **ใช้ Tailwind v4:** `@import '@neondatabase/auth-ui/tailwind'`

ดูวิธีตั้งค่าแบบสมบูรณ์ได้ที่ [UI Components reference](https://neon.com/docs/auth/reference/ui-components)

## ไม่มี directive "use client"

ใน Next.js คอมโพเนนต์ใดก็ตามที่ใช้ `useSession()` หรือ React hooks อื่นๆ ต้องมี `"use client"` อยู่ด้านบนสุดของไฟล์ หากไม่มี Next.js จะมองไฟล์นี้เป็น server component ซึ่งไม่สามารถใช้ React hooks ได้

## Signature ของ createAuthClient ไม่ถูกต้อง

ฟังก์ชัน `createAuthClient` มี signature แตกต่างกันตาม import path:

```typescript
// React SPA — import from @neondatabase/neon-js/auth
import { createAuthClient } from '@neondatabase/neon-js/auth';
createAuthClient(url);
createAuthClient(url, { adapter: BetterAuthReactAdapter() });

// Next.js — import from @neondatabase/auth/next (no arguments, uses proxy)
import { createAuthClient } from '@neondatabase/auth/next';
createAuthClient();
```

ดูตัวอย่างการตั้งค่า client แบบสมบูรณ์ได้ที่ [Next.js quick start](https://neon.com/docs/auth/quick-start/nextjs-api-only) และ [React quick start](https://neon.com/docs/auth/quick-start/react)

## ข้อผิดพลาด OAuth (`redirect_uri_mismatch`, blocked consent, redirect loops)

**`redirect_uri_mismatch` จาก Google (หรือ provider อื่น)**

Authorized redirect URI ใน dashboard ของ provider ต้องตรงกับ callback route ของ Managed Better Auth ทุกตัวอักษร: **`{NEON_AUTH_BASE_URL}/callback/{provider}`** (ตัวอย่างเช่น `.../callback/google`) ดู [การตั้งค่าสำหรับ production](https://neon.com/docs/auth/guides/setup-oauth#production-setup)

ข้อผิดพลาดที่พบบ่อย:

- ลงทะเบียนเฉพาะ marketing site ของคุณ หรือเฉพาะ `callbackURL` จาก `signIn.social()` แทนที่จะเป็น **`{NEON_AUTH_BASE_URL}/callback/{provider}`**
- ใช้ **`NEON_AUTH_BASE_URL`** ของบรานช์หนึ่งในแอป ขณะที่ Google ยังระบุ redirect URI ของ Auth base URL จากอีกบรานช์หนึ่ง

**OAuth สำเร็จ แต่ผู้ใช้ไม่เคยกลับมายังแอปของคุณ**

Managed Better Auth จะ redirect ไปยัง [trusted domains](https://neon.com/docs/auth/guides/configure-domains) เท่านั้น ให้เพิ่มทุก origin ที่คุณใช้ใน **`callbackURL`** (รวมถึง `https://www.example.com` แยกต่างหาก หากคุณใช้ www)

**Google consent screen แสดง hostname ที่ไม่คาดคิด**

Hostname นั้นมาจาก OAuth redirect URI (แอปของคุณเทียบกับ Managed Better Auth) ดู [Google OAuth branding](https://neon.com/docs/auth/guides/setup-oauth#google-oauth-branding)

**Google แจ้งว่าแอปอยู่ในสถานะ Testing / ผู้ใช้นอกบัญชีทดสอบเข้าสู่ระบบไม่ได้**

เพิ่มผู้ทดสอบใน Google Cloud Console หรือเผยแพร่ OAuth consent screen สำหรับการใช้งาน production ดู [Google OAuth branding](https://neon.com/docs/auth/guides/setup-oauth#google-oauth-branding)
