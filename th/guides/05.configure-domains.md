# ตั้งค่า trusted domains

เพิ่มโดเมนของแอปพลิเคชันเพื่อเปิดใช้งานการ redirect สำหรับการยืนยันตัวตนอย่างปลอดภัย

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

เพิ่มโดเมนของแอปพลิเคชันลงใน allowlist ของ Managed Better Auth เพื่อเปิดใช้งานการ redirect สำหรับ OAuth และการยืนยันอีเมลใน production

## ทำไมจึงต้องกำหนดโดเมน

Managed Better Auth จะ redirect ไปยังเฉพาะโดเมนที่อยู่ใน allowlist ของคุณเท่านั้น วิธีนี้ช่วยป้องกันการโจมตีแบบ phishing และการ redirect ที่ไม่ได้รับอนุญาต โดยทำให้แน่ใจว่าผู้ใช้จะถูกส่งไปยัง URL ของแอปพลิเคชันที่ถูกต้องของคุณเท่านั้น

หากไม่ได้เพิ่มโดเมน production ของคุณ การเข้าสู่ระบบด้วย OAuth และลิงก์ยืนยันจะทำงานไม่สำเร็จเมื่อผู้ใช้พยายามเข้าถึงแอปพลิเคชัน

## เพิ่มโดเมน

1. ไปที่ **Console → Auth → Configuration → Domains**
2. กรอกโดเมนพร้อม protocol: `https://myapp.com`
3. คลิก **Add domain**

ทำซ้ำสำหรับทุกโดเมนที่แอปของคุณทำงานอยู่

**หมายเหตุ:** ให้ใส่ protocol (`https://`) และไม่ใส่ trailing slash ตัวอย่างเช่น ใช้ `https://myapp.com` ไม่ใช่ `https://myapp.com/`

## Localhost ถูกตั้งค่าไว้ล่วงหน้า

โดเมนสำหรับการพัฒนาได้รับอนุญาตโดยอัตโนมัติ ดังนั้นคุณไม่จำเป็นต้องเพิ่มโดเมนเหล่านี้:

- `http://localhost:3000`
- `http://localhost:5173`
- พอร์ตใดๆ ของ `localhost`

## โดเมน production

เพิ่มโดเมนทั้งหมดที่ผู้ใช้ใช้เข้าถึงแอปพลิเคชันของคุณ:

- `https://myapp.com`
- `https://www.myapp.com` (หากคุณรองรับ www subdomain)
- `https://app.myapp.com` (หากใช้ subdomain)

## Wildcard domains สำหรับ preview

สำหรับ preview environment ที่มี hostname แบบไดนามิก (ตัวอย่างเช่น Vercel preview deployments) คุณสามารถเพิ่ม **wildcard trusted domain** เช่น `https://*.my-app-preview.vercel.app` ได้ รายการเดียวสามารถ match preview ทุกตัวที่อยู่ภายใต้รูปแบบนั้น แทนที่จะต้องเพิ่มแต่ละ host ทีละรายการ

ใช้กฎเดียวกับโดเมนแบบระบุชัดเจน: ให้ใส่ `https://` (หรือ `http://` ตามความเหมาะสม) และไม่ใส่ trailing slash หลัง pattern

**หมายเหตุ:** รูปแบบ wildcard จะมีผลกับส่วน hostname ที่คุณแทนด้วย `*` โดยทั่วไป production apex domain (ตัวอย่างเช่น `https://myapp.com`) ยังคงต้องเพิ่มเป็นรายการแบบระบุชัดเจน เว้นแต่ wildcard ของคุณจะครอบคลุมโดเมนนั้นอยู่แล้ว

## ปัญหาที่พบบ่อย

**Redirect ถูกบล็อกหลังเข้าสู่ระบบด้วย OAuth:**

- ตรวจสอบว่าโดเมนอยู่ใน allowlist ของคุณ
- ตรวจสอบให้แน่ใจว่าคุณใส่ `https://` (ไม่ใช่ `http://` สำหรับ production)
- ตรวจสอบการสะกดให้ตรงกันทุกตัว (รวมถึง www เทียบกับ non-www)

**ลิงก์ยืนยันไม่ redirect:**

- ลิงก์ยืนยันใช้ domain allowlist เดียวกัน
- เพิ่มโดเมนที่ผู้ใช้ควรถูกส่งไปหลังจากคลิกลิงก์ยืนยัน
