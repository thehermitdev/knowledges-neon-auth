# ตั้งค่า OAuth

เพิ่มการเข้าสู่ระบบด้วย Google, GitHub หรือ Vercel ให้กับแอปพลิเคชันของคุณ

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

OAuth ช่วยให้ผู้ใช้เข้าสู่ระบบด้วยบัญชี Google, GitHub หรือ Vercel ได้ Managed Better Auth จะจัดการโฟลว์ OAuth และสร้างเซสชันหลังจากการอนุญาตสำเร็จ

## โหมดพัฒนา

Google OAuth เปิดใช้งานโดยค่าเริ่มต้นด้วย credential ที่ใช้ร่วมกันสำหรับการพัฒนาและการทดสอบ คุณสามารถเริ่มใช้การเข้าสู่ระบบด้วย Google ได้ทันทีโดยไม่ต้องตั้งค่าใดๆ

**หมายเหตุ:** GitHub และ Vercel OAuth ต้องใช้ credential แบบกำหนดเอง และไม่สามารถใช้งานด้วย credential ที่ใช้ร่วมกันได้ ดูวิธีตั้งค่า OAuth app ของคุณเองที่ [การตั้งค่าสำหรับ production](https://neon.com/docs/auth/guides/setup-oauth#production-setup)

สำหรับ production ให้ตั้งค่า credential ของ OAuth app ของคุณเองสำหรับแต่ละ provider ที่ใช้งาน ดูรายละเอียดที่ [การตั้งค่าสำหรับ production](https://neon.com/docs/auth/guides/setup-oauth#production-setup) ด้านล่าง

## เข้าสู่ระบบด้วย OAuth

เรียก `signIn.social()` พร้อม provider ของคุณ (`"google"`, `"github"` หรือ `"vercel"`) SDK จะส่งผู้ใช้ไปยังหน้าเข้าสู่ระบบของ provider หลังจากผู้ใช้อนุญาตแล้ว provider จะ redirect ไปยัง OAuth callback route ของ Managed Better Auth (ดู [การตั้งค่าสำหรับ production](https://neon.com/docs/auth/guides/setup-oauth#production-setup)) จากนั้น Managed Better Auth จะ redirect เบราว์เซอร์ไปยัง **`callbackURL`** ของคุณ (ใน production ต้องใช้ [trusted domain](https://neon.com/docs/auth/guides/configure-domains))

**Google**

```jsx {6} filename="src/App.jsx"
import { authClient } from './auth';

const handleGoogleSignIn = async () => {
  try {
    await authClient.signIn.social({
      provider: "google",
      callbackURL: window.location.origin,
    });
  } catch (error) {
    console.error("Google sign-in error:", error);
  }
};
```

**GitHub**

```jsx {6} filename="src/App.jsx"
import { authClient } from './auth';

const handleGitHubSignIn = async () => {
  try {
    await authClient.signIn.social({
      provider: "github",
      callbackURL: window.location.origin,
    });
  } catch (error) {
    console.error("GitHub sign-in error:", error);
  }
};
```

**Vercel**

```jsx {6} filename="src/App.jsx"
import { authClient } from './auth';

const handleVercelSignIn = async () => {
  try {
    await authClient.signIn.social({
      provider: "vercel",
      callbackURL: window.location.origin,
    });
  } catch (error) {
    console.error("Vercel sign-in error:", error);
  }
};
```

## จัดการ callback

หลังจากการแลกเปลี่ยนข้อมูล OAuth เสร็จสมบูรณ์ Managed Better Auth จะ redirect เบราว์เซอร์ไปยัง **`callbackURL`** ของคุณ จากนั้นให้โหลดหรือรีเฟรชสถานะเซสชันใน client:

```jsx {4-9} filename="src/App.jsx"
import { authClient } from './auth';

useEffect(() => {
  authClient.getSession().then(({ data }) => {
    if (data?.session) {
      setUser(data.session.user);
    }
    setLoading(false);
  });
}, []);
```

## URL สำหรับ redirect แบบกำหนดเอง

ระบุ URL ที่แตกต่างกันสำหรับผู้ใช้ใหม่หรือเมื่อเกิดข้อผิดพลาด:

```jsx {3-5} filename="src/App.jsx"
await authClient.signIn.social({
  provider: "google", // or "github", "vercel"
  callbackURL: "/dashboard",
  newUserCallbackURL: "/welcome",
  errorCallbackURL: "/error",
});
```

## การตั้งค่าสำหรับ production

สำหรับ production ให้ตั้งค่า credential ของ OAuth app ของคุณเอง GitHub และ Vercel OAuth ต้องใช้ credential แบบกำหนดเอง ส่วน Google OAuth สามารถใช้ credential ที่ใช้ร่วมกันระหว่างการพัฒนาได้ แต่ควรใช้ credential แบบกำหนดเองใน production

### 1. ลงทะเบียน redirect URI กับแต่ละ provider

Managed Better Auth ใช้ callback route ของ [Better Auth](https://www.better-auth.com/) สำหรับแต่ละ OAuth provider ที่คุณเปิดใช้งาน ให้ลงทะเบียน redirect URI ตามรูปแบบนี้:

```text
{NEON_AUTH_BASE_URL}/callback/{provider}
```

ใช้ **Auth base URL** จาก Neon Console สำหรับบรานช์นั้น ภายในแอปของคุณ ค่านี้มักเป็นค่าของ `NEON_AUTH_BASE_URL` หรือ `VITE_NEON_AUTH_URL` หรือ URL ที่คุณส่งให้ `createAuthClient` อย่าเพิ่ม trailing slash ก่อน `/callback`

แทนที่ `{provider}` ด้วย `google`, `github` หรือ `vercel`

ตัวอย่าง authorized redirect URI สำหรับ Google:

```text
https://ep-example.neonauth.us-east-2.aws.neon.tech/neondb/auth/callback/google
```

ไม่ว่าคุณจะใช้ [Next.js auth proxy](https://neon.com/docs/auth/reference/nextjs-server#auth-handler) (`app/api/auth/[...path]/route.ts`) หรือเรียก Managed Better Auth จากเบราว์เซอร์ provider จะ redirect ไปยัง **`{NEON_AUTH_BASE_URL}/callback/{provider}`** สำหรับบรานช์นั้น

**สำคัญ: อย่าสับสนระหว่าง URL สองประเภทที่แตกต่างกัน**

อาร์กิวเมนต์ **`callbackURL`** ใน `signIn.social()` คือปลายทางที่ผู้ใช้จะไปถึง **หลังจาก** Managed Better Auth ดำเนินโฟลว์เสร็จแล้ว URL นี้ต้องอยู่บน origin ที่คุณเพิ่มไว้ใน [trusted domains](https://neon.com/docs/auth/guides/configure-domains)

**authorized redirect URI** ของ provider คือปลายทางที่ Google (หรือ GitHub และ provider อื่นๆ) ส่งเบราว์เซอร์ไป **ระหว่าง** OAuth handshake ค่านี้ต้องเป็น **`{NEON_AUTH_BASE_URL}/callback/{provider}`** ไม่ใช่หน้าแรกของแอปหรือเพียง `callbackURL`

การใช้เฉพาะ URL ของเว็บไซต์การตลาดใน Google Cloud Console หรือใช้เพียง `callbackURL` เป็นสาเหตุที่พบบ่อยของ `redirect_uri_mismatch`

**Google Cloud Console**

สร้าง OAuth client โดยกำหนด application type เป็น **Web application** ภายใต้ **Authorized redirect URIs** ให้เพิ่ม **`{NEON_AUTH_BASE_URL}/callback/google`** สำหรับแต่ละบรานช์หรือสภาพแวดล้อม (production, การทดสอบภายในเครื่องกับบรานช์, previews) ภายใต้ **Authorized JavaScript origins** ให้เพิ่ม origin ที่ UI ของคุณทำงานอยู่ (ตัวอย่างเช่น `http://localhost:5173`, `https://myapp.com`) เมื่อ Google กำหนดให้ต้องมี และเพิ่ม origin ของ Managed Better Auth (scheme และ host ของ `NEON_AUTH_BASE_URL`) หากจำเป็น

**GitHub**

กำหนด **Authorization callback URL** เป็น **`{NEON_AUTH_BASE_URL}/callback/github`**

**Vercel**

ทำตาม [เอกสาร OAuth app ของ Vercel](https://vercel.com/docs/sign-in-with-vercel/manage-from-dashboard#create-an-app) และลงทะเบียน **`{NEON_AUTH_BASE_URL}/callback/vercel`**

### 2. เพิ่ม trusted domains สำหรับแอปของคุณ

ก่อนทดสอบ OAuth ใน production ให้เพิ่มทุก origin ที่คุณส่งเป็น **`callbackURL`** (รวมถึง URL ที่เกี่ยวข้อง) ลงใน allowlist ของ Managed Better Auth ดูรายละเอียดที่ [ตั้งค่า trusted domains](https://neon.com/docs/auth/guides/configure-domains)

### 3. สร้าง OAuth apps และใส่ credentials ลงใน Neon

1. สร้าง OAuth apps กับ provider ของคุณ:
   - [การตั้งค่า Google OAuth](https://developers.google.com/identity/protocols/oauth2/web-server) (ดู [การสร้างแบรนด์ Google OAuth](https://neon.com/docs/auth/guides/setup-oauth#google-oauth-branding) ด้านล่างก่อนเปิดใช้งานจริง)
   - [การตั้งค่า GitHub OAuth](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app)
   - [การตั้งค่า Vercel OAuth](https://vercel.com/docs/sign-in-with-vercel/manage-from-dashboard#create-an-app)
2. ใน Neon Console ให้เปิด **project** ของคุณ เลือก **branch** เปิด **Auth** จากนั้นกรอก **Client ID** และ **Client Secret** สำหรับแต่ละ provider

Managed Better Auth จะใช้ credential ที่คุณตั้งค่าไว้สำหรับบรานช์นั้น

### บรานช์และ preview deployments

แต่ละบรานช์มี **`NEON_AUTH_BASE_URL`** ของตัวเอง ให้ลงทะเบียน **`{NEON_AUTH_BASE_URL}/callback/google`** (รวมถึง provider อื่นที่คุณใช้งาน) สำหรับทุกบรานช์ที่คุณใช้ทดสอบ (ตัวอย่างเช่น preview databases)

สำหรับ preview deployments, trusted domains รองรับ **รูปแบบ wildcard** (ตัวอย่างเช่น `https://*.my-app-preview.vercel.app`) ทำให้คุณครอบคลุม preview host จำนวนมากได้โดยไม่ต้องระบุทีละรายการ ดูรายละเอียดที่ [ตั้งค่า trusted domains](https://neon.com/docs/auth/guides/configure-domains), [การยืนยันตัวตนแบบแตกบรานช์](https://neon.com/docs/auth/branching-authentication) และ API สำหรับ [trusted domains](https://neon.com/docs/reference/api/auth/add-branch-neon-auth-trusted-domain)

## การสร้างแบรนด์ Google OAuth

เมื่อใช้ Google OAuth credential ของคุณเอง ผู้ใช้จะเห็น consent screen ก่อนเข้าสู่ระบบ Google จะแสดงข้อความ **Continue to** ซึ่งใช้ hostname จาก OAuth redirect URI ของคุณ (ดู [การตั้งค่าสำหรับ production](https://neon.com/docs/auth/guides/setup-oauth#production-setup)) โดยทั่วไปจะเป็นโฮสต์ที่ Neon จัดการให้จาก **`NEON_AUTH_BASE_URL`** ของคุณ

หากยังไม่ได้ตั้งค่าการสร้างแบรนด์บน OAuth consent screen ให้สมบูรณ์ (ชื่อแอป, อีเมลสำหรับการช่วยเหลือ และ authorized domains ใน Google Cloud Console) consent UI อาจดูทั่วไปหรือทำให้ผู้ใช้สับสนได้ แม้ว่า Client ID และ Client Secret ของคุณจะถูกต้องก็ตาม

หากต้องการแสดงชื่อแอปของคุณบน consent screen:

1. ไปที่ [Google Cloud Console → OAuth consent screen](https://console.cloud.google.com/auth/branding)
2. กรอกข้อมูลแอปที่จำเป็น:
   - **App name**: ชื่อที่ผู้ใช้จะเห็นบน consent screen
   - **User support email**: อีเมลสำหรับผู้ใช้ที่มีคำถามเกี่ยวกับ auth
   - **Developer contact information**: อีเมลของคุณ (ไม่แสดงให้ผู้ใช้เห็น)
3. ภายใต้ **Authorized domains** ให้เพิ่มโดเมนของแอปคุณ (ตัวอย่างเช่น `myapp.com`)
4. บันทึกการเปลี่ยนแปลง

**สำคัญ: แอปสาธารณะต้องผ่านการตรวจสอบ**

แอปที่อยู่ในสถานะ **Testing** อนุญาตเฉพาะบัญชี Google ที่คุณเพิ่มเป็น **test users** เท่านั้น ผู้ใช้อื่นจะพบข้อผิดพลาดหรือโฟลว์ consent ถูกบล็อกโดยไม่ขึ้นอยู่กับการสร้างแบรนด์ หากต้องการแสดงแบรนด์ production และอนุญาตผู้ใช้ทั้งหมด ให้เผยแพร่ OAuth consent screen และดำเนินการตรวจสอบของ Google ให้เสร็จเมื่อจำเป็น โดยทั่วไปการตรวจสอบใช้เวลาสองสามวันทำการ แต่อาจใช้เวลานานกว่านั้นขึ้นอยู่กับ scopes ที่คุณร้องขอ
