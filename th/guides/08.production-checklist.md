# เช็กลิสต์ Auth สำหรับ production

การตั้งค่าที่จำเป็นก่อนเปิดใช้งาน Managed Better Auth จริง

**หมายเหตุ: Beta**

**Managed Better Auth** อยู่ในสถานะ Beta คุณสามารถส่งความคิดเห็นผ่าน [Discord](https://discord.gg/92vNTzKDGp) หรือผ่าน [Neon Console](https://console.neon.tech/app/projects?modal=feedback)

ดำเนินการตามขั้นตอนเหล่านี้ให้ครบก่อนนำแอปพลิเคชันที่ใช้ Managed Better Auth ขึ้น production

## เช็กลิสต์ Auth สำหรับ production

- [ ] [1. ตั้งค่า trusted domains](https://neon.com/docs/auth/guides/configure-domains)
    เพิ่ม production domain ของคุณเพื่อเปิดใช้งานการ redirect สำหรับ OAuth และการยืนยันอีเมล
- [ ] [2. ตั้งค่า custom email provider](https://neon.com/docs/auth/production-checklist#email-provider)
    แทนที่ shared SMTP (`auth@mail.myneon.app`) ด้วยบริการอีเมลของคุณเอง เพื่อให้ส่งอีเมลได้อย่างน่าเชื่อถือและมีลิมิตสูงขึ้น นอกจากนี้ยังต้องใช้ custom email provider หากคุณต้องการใช้ลิงก์ยืนยันแทนรหัสยืนยัน
- [ ] [3. ปรับแต่ง application name](https://neon.com/docs/auth/production-checklist#application-name)
    กำหนดชื่อที่ผู้ใช้จะเห็นในข้อความ auth ที่แสดงต่อผู้ใช้ ใช้กับ integration ของ Managed Better Auth โดยค่าเริ่มต้นจะใช้ชื่อโปรเจ็กต์ Neon
- [ ] [4. ตั้งค่า OAuth credentials (หากใช้ OAuth)](https://neon.com/docs/auth/guides/setup-oauth#production-setup)
    ตั้งค่า Google และ GitHub OAuth apps ของคุณเองเพื่อแทนที่ shared development keys
- [ ] [5. เปิดใช้งานการยืนยันอีเมล (แนะนำ)](https://neon.com/docs/auth/guides/email-verification)
    **การยืนยันอีเมลไม่ได้เปิดใช้งานโดยค่าเริ่มต้น** เนื่องจากทุกคนสามารถสมัครสมาชิกแอปพลิเคชันของคุณได้ การเปิดใช้งานการยืนยันอีเมลจึงเพิ่มขั้นตอนสำคัญเพื่อยืนยันว่าผู้ใช้เป็นเจ้าของอีเมลของตนจริง
- [ ] [6. ปิด localhost access](https://neon.com/docs/auth/production-checklist#localhost-access)
    ปิดการตั้งค่า "Allow Localhost" ในหน้า **Settings** → **Auth** ของโปรเจ็กต์ การตั้งค่านี้เปิดใช้งานโดยค่าเริ่มต้นสำหรับ development แต่ควรปิดใน production เพื่อเพิ่มความปลอดภัย

## ผู้ให้บริการอีเมล

Managed Better Auth ใช้ shared SMTP provider (`auth@mail.myneon.app`) โดยค่าเริ่มต้นสำหรับ development และการทดสอบ สำหรับ production ให้ตั้งค่าผู้ให้บริการอีเมลของคุณเองเพื่อเพิ่มความสามารถในการส่งอีเมลถึงผู้รับและเพิ่มลิมิตการส่ง

Custom SMTP provider จะใช้ที่อยู่ผู้ส่งของคุณ แต่ยังคงส่งเทมเพลตอีเมลเริ่มต้นของ Neon หากต้องการควบคุมแบรนด์ เนื้อหา และเทมเพลต HTML ของอีเมลอย่างเต็มรูปแบบ ให้ใช้เว็บฮุกเพื่อดัก event ของอีเมลและส่งผ่านบริการอีเมลของคุณเอง ดู [ปรับแต่งอีเมล](https://neon.com/docs/auth/guides/customize-emails)

### ตั้งค่า custom SMTP

ในหน้า **Settings** → **Auth** ของโปรเจ็กต์ ให้ตั้งค่าผู้ให้บริการอีเมล:

1. เลือก **Custom SMTP provider**
2. กรอก SMTP credentials:
   - **Host**: hostname ของ SMTP server (ตัวอย่างเช่น `smtp.gmail.com`)
   - **Port**: พอร์ต SMTP (โดยทั่วไปใช้ `465` สำหรับ SSL หรือ `587` สำหรับ TLS)
   - **Username**: username ของ SMTP
   - **Password**: รหัสผ่าน SMTP หรือ app-specific password
   - **Sender email**: อีเมลที่ใช้เป็นผู้ส่ง
   - **Sender name**: ชื่อที่แสดงสำหรับอีเมลที่ส่ง
3. คลิก **Save**

### ข้อกำหนดของผู้ให้บริการอีเมล

- **ลิงก์ยืนยัน**: ต้องใช้ custom email provider
- **รหัสยืนยัน**: ใช้งานได้กับ shared หรือ custom email provider
- **รีเซ็ตรหัสผ่าน**: ใช้งานได้กับ shared หรือ custom email provider

**หมายเหตุ:** shared email provider (`auth@mail.myneon.app`) เหมาะสำหรับ development และการทดสอบ สำหรับแอปพลิเคชัน production ให้ใช้ custom email provider เพื่อเพิ่มความสามารถในการส่งอีเมลถึงผู้รับและหลีกเลี่ยง rate limit

## ชื่อแอปพลิเคชัน

Managed Better Auth ใช้ชื่อแอปพลิเคชันในข้อความ auth ที่แสดงต่อผู้ใช้ เช่น อีเมลยืนยันและการรีเซ็ตรหัสผ่าน โดยค่าเริ่มต้นจะใช้ชื่อโปรเจ็กต์ Neon การตั้งค่านี้ใช้ได้เฉพาะ integration ของ Managed Better Auth

หากต้องการกำหนดชื่อแอปพลิเคชันแบบกำหนดเอง:

1. ไปที่ **Auth** ในโปรเจ็กต์ Neon
2. เลือกแท็บ **Configuration**
3. ในแผง **Project Info** ให้แก้ไขฟิลด์ **Application Name**

แต่ละบรานช์จัดการ application name ของตัวเองแยกจากกัน ดังนั้นบรานช์ preview และ development จึงสามารถใช้ชื่อที่แตกต่างจาก production ได้

คุณยังสามารถอัปเดต application name ผ่าน API ได้ ดู [อัปเดตการตั้งค่า auth](https://neon.com/docs/auth/guides/manage-auth-api#update-auth-configuration)

## การเข้าถึงจาก Localhost

การตั้งค่า "Allow Localhost" ในหน้า **Settings** → **Auth** ของโปรเจ็กต์เปิดใช้งานโดยค่าเริ่มต้น เพื่ออนุญาต request การยืนยันตัวตนจาก localhost ระหว่าง development

### ปิดสำหรับ production

สำหรับสภาพแวดล้อม production ให้ปิดการตั้งค่านี้เพื่อเพิ่มความปลอดภัย:

1. ไปที่ **Settings** → **Auth** ในโปรเจ็กต์ Neon
2. ค้นหา toggle **Allow Localhost**
3. ปิด toggle

**สำคัญ:** เปิด "Allow Localhost" เฉพาะสำหรับ local development เท่านั้น การปิดการตั้งค่านี้ใน production จะป้องกัน request การยืนยันตัวตนที่ไม่ได้รับอนุญาตจาก localhost และช่วยเพิ่ม security posture ของแอปพลิเคชัน
